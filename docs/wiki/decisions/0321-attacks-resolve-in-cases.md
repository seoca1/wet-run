# ADR-0321: 공격은 여러 확률 케이스로 해결된다 — SRW식 명중/방어/급소

**상태**: Accepted (오너 지시) · **기본 표는 0** (오너가 정하는 다이얼)
**날짜**: 2026-11-18
**결정자**: 사용자 (오너 지시: *"전투 공격에 슈퍼로봇대전의 크리티컬, 회피 등을 응용해서 여러 케이스를 확률적으로 도입하고 싶어"*)
**우선순위**: P1 (전투 · 밸런스)

## 컨텍스트 (Context)

지금까지 **모든 공격이 명중했다.** 플레이어 카드도, ICE 자동공격도 100% 적중이고, 전투에서 유일한 확률은 **크리티컬 한 가지**였다(플레이어 15%, `aggressive` ICE +5%). "회피"는 있었지만 굴림이 아니라 **피해의 15%를 결정적으로 깎는 세금**이었다(`applyPlayerMitigation`) — 즉 회피라고 부르지만 회피가 아니었다.

오너가 SRW(슈퍼로봇대전)의 모양을 요청했다: 공격마다 **빗나감 / 막음 / 명중 / 급소**가 굴림으로 갈리는 구조.

## 결정 (Decision)

**공격 하나를 여러 케이스로 해결하는 순수 모듈을 만들고, 확률표를 오너의 다이얼로 둔다.**

```
[0, miss)          -> MISS    피해 0
[miss, miss+guard) -> GUARD   피해 절반
[miss+guard, 1)    -> HIT     정상
   (+ 급소는 기존 combat_engine 의 크리 밴드가 담당 — 다시 굴리지 않는다)
```

- **한 번의 굴림**, 밴드는 위에서 아래로 읽는다 — 한 케이스를 올려도 다른 케이스의 밴드가 조용히 움직이지 않는다.
- **`cloak`(evade 15%)가 진짜 회피가 된다**: 평평한 −15% 피해가 아니라 **15% 확률로 공격이 통째로 빗나감**.
- **방어구(shield pool)는 케이스 뒤에 온다**: 빗나간 공격은 배리어를 소모하지 않는다(필요 없었으므로).
- **순서 고정**: 케이스 → 크리 → 방어구. 아키타입에 따라 굴림 순서가 바뀌지 않는다.

### ⚠️ 기본 표는 0 이다 — 그리고 그 이유가 측정이다

`INCOMING_BASE_ODDS = { missPct: 0, guardPct: 0 }`.

측정: `miss 6 / guard 12` — 평균적으로 들어오는 피해의 **12%만** 깎는 표 — 가 미션 곡선을 이렇게 옮겼다:

| 등급 | 이전 | 표 6/12 | 차이 |
| --- | --- | --- | --- |
| g3 | 84.5% | **93.8%** | +9.3 |
| g4 | 84.4% | **92.2%** | +7.8 |
| g5 | 27.1% | **46.9%** | +19.8 |
| g6 | 34.4% | **60.4%** | +26.0 |

단일 교전 기준으로는 g4 **+42pp**(50→92). **평균 12%를 깎았는데 왜 이렇게 큰가** — **분산이 본질**이기 때문이다. g5·g6 은 **한 번의 싸움에서 죽는다**(ADR-0319 실측). 그 상황에서 "피해 12% 감소"는 3대째에 죽는 것을 3.4대째로 미룰 뿐이지만, **"6% 확률로 아무것도 안 맞음"은 치명타 한 대를 통째로 지운다 — 한 대를 피하면 런이 산다.**

즉 SRW식 케이스는 **작은 맛보기가 아니라 큰 방어 버프**다. 그래서 기본 표를 0 으로 두고, **오너가 값을 정하면 그에 맞춰 ICE 피해를 올리는 것**을 전제로 한다(수치는 오너 영역).

### 플레이어 공격은 빗나가지 않는다 (지금은)

Jev `choice`(범위): `incoming_attacks_can_miss_only` **0.44** · `no_miss_only_crit_guard_graze` 0.33 · `player_attacks_can_miss_only` 0.20 · `both_sides_miss` 0.03 — **confidence 0.25 로 낮아 자동 적용하지 않고 표면화**한다. 다만 상위 두 옵션(0.44+0.33)이 일치하는 것: **카드는 헛방이면 안 된다.** 카드는 자원이자 한 턴이고, ADR-0251 rule 5 는 손패가 화면이 할 일을 말하라고 요구한다. `PLAYER_ODDS` 가 존재하므로 오너가 숫자 하나로 켤 수 있고, 기본은 0 이다.

## 결과 (Consequences)

### `cloak` 의미 변경의 측정 (기본 표 0 인 상태의 실제 변화)

| 지표 | 이전 | 이후 |
| --- | --- | --- |
| 단일 교전 g5 | 83.9% | **70.6%** |
| 단일 교전 g6 | 32.3% | **47.0%** |
| 미션 g3 / g4 / g5 | 84.5 / 84.4 / 27.1 | 83.4 / 83.1 / **25.9** |
| 미션 g6 | 34.4% | **42.2%** |

**g5 는 어려워지고 g6 는 쉬워진다** — 평평한 감소는 연속 피격에서 생존을 *보장*하지만, 굴림은 보장하지 않는다(운이 안 따르면 4대를 그대로 맞는다). 반대로 한 방에 죽는 등급에서는 굴림이 더 낫다. 같은 평균, 다른 분포.

### 그 밖

- **기본 표가 0 이고 회피가 없으면 굴림 자체가 없다** → 시드 스트림이 그대로라 **기록된 곡선이 byte-identical**(`balance_sim` 기준선 행이 그 증거다).
- 로그: 케이스가 평범한 명중이면 **아무 말도 하지 않는다**(`[HIT]` 는 소음). 빗나감·막음만 ` [MISS]` · ` [GUARD]`.
- 표시되는 피해 숫자는 **실제로 HP 에 닿은 값**(케이스·방어구 이후)이다.

### 열린 질문 (오너 몫)

- **(a) 기본 표의 값.** 위 표가 그 값의 가격이다. 값을 정하면 ICE 피해를 그에 맞춰 올려야 한다(현재 곡선은 그 조정 없이는 훨씬 쉬워진다).
- **(b) 플레이어 쪽 표.** `PLAYER_ODDS` — Jev 는 반대했고(0.03), 신뢰도도 낮다. 켜면 카드가 헛방이 되고 rule 5 와 긴장한다.
- **(c) `guard` 의 출처.** 지금은 기본 표(0)뿐이다. 카드로 줄 것인가(`ward`·`barrier`?), 아니면 등급별 기본값으로 둘 것인가.
- **(d) 급소를 케이스 표로 옮길 것인가.** 지금은 `combat_engine` 의 크리 밴드가 담당한다(재굴림 방지).
