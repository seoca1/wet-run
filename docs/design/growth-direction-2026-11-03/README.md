# 성장 연출 시안 — 검토 대기 (2026-11-03)

> **상태: 시안 (decision pending).** 아직 ADR 이 아니다. 오너가 고르면 그때 ADR + 구현으로 간다.
>
> **만든 방식**: Manus(max 프로필)에 이 게임의 실제 제약을 주고 시안 4안을 받았고, **Jev 결정 계층**으로
> 제약 적합성을 게이트했다. Manus 원문은 [manus-raw.md](manus-raw.md) · [manus-structured.json](manus-structured.json).

## 왜 필요한가

ADR-0261 로 획득 3박자(소리·멈춤·표시)는 들어갔지만 **연출은 텍스트 색 변화가 전부**다.
오너: "성장은 재미 요소 중 하나라서 중요하다." 카드를 얻는 순간이 **사건처럼** 느껴져야 한다.

## 기술 제약 (시안이 지켜야 하는 것)

이 저장소를 실제로 읽고 확인한 사실:

| 사실 | 의미 |
|---|---|
| **VFX 는 전투 화면 경로에서만 합성된다** (`composeCombatScreen`) | loot/매트릭스 화면은 자기 격자를 매 프레임 새로 그린다. `vfxInstances` 를 loot 에 그냥 붙이면 안 된다 |
| **표시 전용·벽시계 선례 2개가 `main.ts` 안에 있다** — `matrixTravelFrame`(220ms 이동) 과 `pressFeedback` | 연출은 **리듀서 밖**에서 같은 모양으로 만들 수 있다. 이게 정답 경로다 |
| `renderRunScreen(..., matrixTravel)` 이 프레임을 인자로 받아 그린다 | 성장 연출도 같은 방식으로 인자를 하나 더 받으면 된다 |
| `SFX_IDS.EQUIP` 는 이미 ADR-0261 에서 배선됨 | 소리는 추가 작업 없음 |
| loot 화면 세로 여유: 80×50 위 6행·아래 10행, 40×60 위 6행·아래 **16행** | 연출 공간은 충분하다 |
| `data_acquired` VFX 는 존재하고 **실제로 렌더된다**(cache 노드 → combat 진입) | 전투 밖으로 끌어오는 것은 별도 작업 |

## Manus 시안 4안 (요약)

| 안 | 컨셉 | 비용 | 확신 | Jev 게이트 |
|---|---|---|---|---|
| **1. TERMINAL COMMIT** | 카드가 "등장"하는 게 아니라 기업 터미널이 **불완전한 데이터를 덱에 강제 커밋**한다. `PROGRAM SLOT` / `DATA LINK ... OPEN` / `SIGNATURE` / `DECK COMMIT [####] 100%` / `[+] PROGRAM ACQUIRED` 4단계 고정 프레임, ~420ms | 작음 | 높음 | ✅ 위반 없음 (0.24) |
| **2. GHOST TRACE** | 선택 행에서 덱으로 **고정 ASCII 연결선** `──╼ DECK[07]`, `DATA RESIDUE: KRAKEN` | 중간 | 중간 | ❌ **제외 — 덱 슬롯 번호는 게임 상태에 없다** (0.70) |
| **3. COLD BOOT / PROGRAM WAKE** | `PROGRAM WAKE` / `BOOT .... READY` / `[+] ACQUIRED` 부팅 은유 | 중간 | 높음 | ⚠️ **문구 수정 필요** — `READY` 는 과대 주장 (0.61) |
| **4. ARRIVAL: ROUTE HANDOFF** | 매트릭스 도착에서 `+ PROGRAM: KRAKEN` / `ROUTE HANDOFF COMPLETE` 로 성장을 다음 경로 선택에 연결 | 작음~중간 | 높음 | ✅ 위반 없음 (0.18) |

### 추천안 (Manus 1위 · Jev 0.97/conf 0.96 — 일치)

**안1 + 안4 를 하나의 흐름으로 결합.**

```text
① 커밋 (loot 화면)                    ② 인수인계 (매트릭스 도착)
┌────────────────────────────┐        ┌──────────────────────────────┐
│ DATA SALVAGE               │        │ ICE MATRIX     HP 78/100     │
│ HP 78/100   +4,075 credits │        │                              │
│ NEW PROGRAM                │        │   [ICE]──[DATA]──[ICE]       │
│                            │        │            │                 │
│  ┌──────────────────────┐  │  ENTER │       ┌────▼────┐            │
│  │ PROGRAM SLOT 01      │  │ ─────► │       │  YOU    │  + PROGRAM │
│  │ > 1 KRAKEN  [PIERCE 2]│ │        │       │         │    KRAKEN  │
│  │ DECK COMMIT [#####]100%│ │        │       └─────────┘            │
│  │ [+] PROGRAM ACQUIRED │  │        │  Took Kraken. Choose an      │
│  └──────────────────────┘  │        │  adjacent route — healed 78  │
│ 2 INSPIRE    3 DECRYPT     │        │                              │
│ ENTER: continue            │        │                              │
└────────────────────────────┘        └──────────────────────────────┘
```

**왜 좋은가 (Manus 논지)**: "화려한 보상"이 아니라 **"기업 시스템에 비인가 프로그램을 강제 등록하는 일"**
처럼 보인다 — 1980년대 깁슨 톤에 맞는다. 재미는 색 변화가 아니라 **상태가 단계적으로 확정되고,
그 결과가 다음 화면의 경로 선택으로 즉시 이어진다**는 데서 온다.

**비용이 작은 이유**: 새 VFX 종류도, 새 이벤트 버스도, 리듀서 상태도 필요 없다.
`matrixTravelFrame` 과 똑같은 **표시 전용 프레임 2개**만 `main.ts` 에 둔다.

## Jev 가 잡아낸 두 가지 (반영 필요)

### ❌ 안2 제외 — 존재하지 않는 값을 쓴다
`DECK[07]` 의 "07" 은 **덱 슬롯 인덱스**인데 게임 상태에 그런 값이 없다. Jev noul **0.70**(임계 0.6 초과) →
어포던스 진실성 위반. Manus 자신도 "슬롯 숫자 없이 축약하면 임팩트가 준다"고 3위로 내렸다. **만들지 않는다.**

### ⚠️ 안3 문구 수정 — `READY` 는 과대 주장
새 카드는 손패에 즉시 오지 않는다. **뽑기 더미에 들어가 다음 손패 순환 때 등장**한다.
Jev noul **0.61** → `READY`(지금 쓸 수 있다)는 거짓. 만약 안3 을 쓴다면 `READY` → `QUEUED`/`STAGED`
처럼 **더미에 들어갔다는 사실**을 말해야 한다.

## "이건 만들지 마라" (Manus 제시 + 제약에서 도출)

1. **카드가 화면을 가로질러 날아가 HUD에 꽂히는 연출** — 40×60 에서 폭이 없다. 가로 스크롤·카드 위젯 금지와 충돌.
2. **VFX 가 끝날 때까지 입력을 막는 연출** — 입력 락·대기 금지 위반.
3. **전투용 `data_acquired` 를 loot 화면에 그대로 주입** — 화면별 렌더 계약이 흐려진다.
4. **랜덤 파티클·랜덤 글리치·랜덤 미리보기** — RNG 소비는 밸런스 byte-identical 위반.
5. **축하 폭죽·금색 별·레벨업 게이지·콤보 팡파르** — 깁슨 톤 파괴.
6. **없는 덱 슬롯·프로그램 레벨·희귀도·온라인 플래그** — 안2 가 정확히 이 함정이었다.
7. **Y/N 확인창·축하 메시지를 닫기 위한 추가 단계** — 금지된 Y/N 문법이고 성장 리듬을 늘어뜨린다.

## 구현 시 형태 (Manus 권고 · 코드 사실과 일치)

리듀서에 새 상태를 넣지 않는다. `main.ts` 표시 전용 계층에 두 개만:

```ts
lootCommitFrame:    { startedAtMs: number; cardIndex: number } | null
matrixArrivalFrame: { startedAtMs: number; cardName: string }  | null
```

- 리듀서의 카드 획득 액션이 **성공한 직후** `lootCommitFrame` 시작 (순서를 지켜야 진실하다).
- ENTER 처리 시 loot 표시 상태를 지우고, 매트릭스 진입에서 `matrixArrivalFrame` 시작.
- **애니메이션 종료를 리듀서로 보내지 않는다.** 프레임 종료는 렌더 시각 비교로만 판단.
- `reduced-motion` 이면 프레임 변화를 건너뛰고 **최종 문구만** 그린다:
  `PROGRAM SLOT: COMMITTED` / `[+] PROGRAM ACQUIRED` / `ENTER: continue`.
