# ADR-0265: 전투 정지(COST 상한)와 직접 컨트롤 소크 하네스

**상태**: Accepted (발견·검증 방법) / **미수정 (수정은 오너 결정 대기)**
**날짜**: 2026-11-03
**결정자**: 오너 "이번엔 전투 중에 멈췄어. 직접 컨트롤하는 진행 테스트를 충분히 많이 해야겠어. 계획을 세우고 통계적으로 의미있는 검증을 할 수 있게 진행해줘."
**우선순위**: P0 (블로킹 — 전투가 진행되지 않음) + P2 (검증 인프라)
**관련**: [ADR-0263 — 죽음 화면 탈출](./0263-defeat-screen-must-be-escapable.md) · [ADR-0251 — 어포던스 진실성 §5](./0251-truthful-program-affordance-and-combat-integrity-rules.md) · [ADR-0252 — 런 종료/저장](./0252-run-end-and-save-timing.md) · [ADR-0248 — ALARM/COST 명칭](./0248-alarm-meter-naming.md) · ADR-0240/0242 (idle alarm / archetype alarm)

> **전투가 멈춘다.** COST 가 상한에 닿으면 모든 프로그램이 거절되고, **턴은 손패를 다 써야만**
> 진행되는데 쓸 수 있는 카드가 없다. `GameAction` 에 "턴 넘기기"가 없으므로 턴은 영원히 가지 않고,
> 유일한 출구는 `ESC`(JACK OUT) = **런 상실**이다. 오너가 "전투 중에 멈췄다"고 한 상태다.

## 컨텍스트 (Context)

지금까지 결함 3건 중 2건이 **손으로 하나씩** 발견됐다(ADR-0263 죽음 화면, 이번 전투 정지).
손 발견은 **발견 편향**이 있다 — 우연히 밟은 것만 찾고, 비율을 모른다. "한 번 봤다"는 비율이 아니다.
그래서 이 ADR 은 **두 가지**를 남긴다: 확정한 결함, 그리고 그것을 세는 **도구**.

### 확정한 결함 (코드 + 실측)

```
useProgram                       alarm + cost > 100  →  거절
applyCombatAction(use_program)   손패 길이가 그대로면  →  조기 반환
                                 (적 턴 없음 · 손패 리필 없음)
GameAction                       "턴 넘기기" 없음
tickAlarm                        alarmLevel(TRACE) 만 올린다 — COST(player.alarm) 는 전투 중 줄지 않는다
```

실측(독립 headless Chromium, preview 5195, 실제 전투):

```
COST 상한 + 손패 5장 → blocked: true
  Enter · Space · 숫자 · 방향키  →  전부 변화 없음
  20초 무입력                   →  적이 때리지 않음, COST 그대로
  ESC                          →  "Jacked out — mission failed"   ← 유일한 출구 = 런 상실
```

즉 **"막히면 더 못 때리고, 그냥 진다"** 가 아니라 **"막히면 게임이 서고, 포기해야 한다"** 이다.

## 결정 (Decision)

### 1) 검증 도구: 직접 컨트롤 소크 하네스 (`web/e2e/soak_playthrough.spec.ts`, `npm run soak`)

실제 빌드를 실제 브라우저에서 **실제 키로** 여러 번 플레이하고 정지를 분류·집계한다.

| 원칙 | 이유 |
|---|---|
| **실제 키만** (`wetrun.state` 를 쓰지 않는다) | 리듀서·컨트롤러를 우회하면 그건 다른 게임을 재는 것 |
| **정책이 몰고, 스윕은 진단만** | 전체 키 스윕은 정책 행동이 아무것도 못 바꿨을 때만 — 건강한 런을 마구 흔들지 않는다 |
| **"정책이 헤맸다" ≠ "게임이 멈췄다"** | 진행 키를 **두 번** 스윕해도 무변화일 때만 정지 (거절 메시지 같은 1회성 변화를 흡수) |
| **포기 키 분리** | `Escape` 와 `q` 는 **둘 다** `jack_out`. 진행 스윕에서 빼고 "포기만 가능"을 **별도 분류**로 |
| **결정적** | 런은 미션에서 시드되고 정책은 상태의 순수 함수 → 같은 (미션, 정책)은 같은 결과. **반복은 정보가 없다** → 미션·정책을 **전수조사** |
| **상한 도달률도 기록** | 정지 분류는 0-cost 카드 유무에 흔들릴 수 있다. `maxAlarm`·`minAffordable` 로 **COST 상한 자체**를 따로 센다 |

분류: `completed` · `failed` · `deadlocked`(어떤 키도 무력) · `only_escape_loses`(진행 키 전부 무력, 포기만 됨)
· `no_end_in_steps`(상태는 변하나 끝에 도달 못함 — 별개 발견).

집계: 결과·정책·등급·정지 phase 분포, Wilson 95% 구간, COST 상한 도달률.

### 2) 발견은 도구가 하고, 수정은 오너가 고른다

정지는 **리듀서 규칙**이라 밸런스에 닿는다. 후보는 D1~D4(턴 패스 / 자동 턴 진행 / ESC 안내 / COST 감소)로
정리했고, 별도 ADR 로 확정한다. 이 ADR 은 **결함과 측정 방법**까지다.

## 결과 (Consequences)

- **발견이 재현 가능해졌다**: 정지 후보는 (미션, 정책, 시드)로 다시 돌리면 같은 상태에서 멈춘다.
- **비율을 말할 수 있게 됐다**: 손 발견 1건 → "N개 셀 중 M개" 로.
- **밸런스 기준선 교차확인**: `balance_sim` 은 `deck[0]` 을 무조건 `use_program` 하므로 상한에서 **헛바퀴**를 돈다.
  실측 결과 시작 덱·전 등급에서 헛바퀴 **0.0%** (전투가 상한 전에 끝난다) → **기준선은 이 정지로 오염되지 않았다.**
  다만 이는 "심이 상한을 만나면 조용히 `won:false` 로 센다"는 사실을 드러낸다 — 심에 상한 도달을 **기록**하는 것은
  별도 개선으로 남긴다(기준선 파일이 바뀌므로).
- `npm run e2e` 는 `SOAK=1` 게이트로 그대로 빠르다.

### 불변

- 하네스는 **게임 코드를 바꾸지 않는다**. 밸런스 접점 0.
- 하네스는 **판정을 실패로 만들지 않는다** — 비율이 산출물이다.

**Notes**:

- 하네스 자체의 버그 **5개**를 개발 중 잡았다(모두 도구 쪽이었다). 앞의 셋을 고치기 전의 수치는 무효다:
  ① 키 목록을 미리 만들어 나중에 누르면 **자기 효과를 못 본다** → 누르고 읽는 구조로
  ② 진행 스윕에 **`q`(=`jack_out`)** 가 섞여 정상 런을 스스로 포기시켰다
  ③ **BYPASS 한 노드**를 미해결로 봐서 같은 노드로 무한히 되돌아갔다
  ④ **거절 메시지가 번갈아 바뀐다** — 상한에서 `1` 은 "Cost too high", 빈 슬롯 `6` 은 "Hand slot 6 is empty" 를 써서
     스윕이 매번 "변화 있음"으로 읽혔다 → 정지가 **한 번도 분류되지 않았다**. 프로젝션에서 **메시지를 분리**(`structural`)해 해결
  ⑤ **idle alarm 이 스스로 `TRACE n/5` 를 쓴다** — 키 없이 텍스트가 바뀌어 정지를 가렸다(④의 수정이 함께 해결)
- **첫 전수조사는 ④ 때문에 16건을 `no_end_in_steps` 로 잘못 분류했다**(수치는 같았고 분류가 틀렸다).
  정정 후 같은 셀이 `only_escape_loses` 로 분류되며 31스텝에 끝난다(잘못 분류될 땐 59~320스텝을 헛돌았다).
- **2026-11-08 갱신 (브라우저 재검증) — 위 수치의 전제 두 개가 틀렸다.**
  ⑴ **"미션 53 × 정책 3 = 159 셀" 은 셀이 아니다.** 미션 보드는 sprawl **33개**만 싣고(ADR-0213)
  `startRun` 의 `ArrowDown` 이 wrap 하므로 159런은 **33미션 × 3정책 = 99 셀**이고 60런이 중복이었다.
  게다가 `mission = run % count` 와 `policy = run % 3` 이 **미션 수가 3의 배수일 때 동기화**되어
  (33이 그렇다) 미션마다 정책이 하나로 고정됐다 — 33미션 중 2개 이상의 정책을 만난 미션은 **0개**.
  ⑵ **"census, not a sample" 도 틀렸다.** 게임은 전투 주사위를 `Math.random` 에서 뽑고 시드하는 것은
  **헤드리스 하네스뿐**이다(`balance_sim` · `mission_survival`). 브라우저 하네스는 시드가 없어 같은
  셀이 매번 달랐다(story trace 3회 = **53/60/58 스텝**). 둘 다 수정(미션 수를 보드에서 파생 · 정책 회전
  분리 · 시드 `Math.random` 주입)했고, 이후 census: **frozen 0/99**(Wilson 95% **0–3.74%**) ·
  completed 73 · failed 23 · `no_end_in_steps` 3 · **11분**(수정 전 159런은 교착이 상한을 태워 4.6시간).
  남은 `no_end_in_steps` 3건은 하네스가 아니라 **ADR-0290 게이트의 BYPASS 소프트락**이었다
  (→ **ADR-0308 로 수정**: clamp 에서 우회 노드 제외. 이후 census `no_end_in_steps` **0**).

## 열린 질문

- **(a) 수정 선택.** D1(턴 패스) / D2(자동 턴 진행) / D3(ESC 안내) / D4(COST 감소). 정지는 리듀서 규칙이라
  밸런스 재측정이 필요하다. 추천은 **D1 + D3**.
- **(b) COST 압박의 의도.** "상한에 닿으면 이긴 fight 도 더 못 때린다"가 설계 의도인지, 아니면 사고인지.
  의도라면 D3(안내)로 충분하고, 사고라면 D1/D2 가 맞다.
- **(c) 심의 상한 기록.** `balance_sim` 이 상한 도달을 세지 않는다. 기준선 파일이 바뀌므로 별도 슬라이스.
