# ADR-0318: 런은 계약이다 — 3미션 연쇄, 그리고 완주가 부보다 먼저 온다

**상태**: Accepted
**날짜**: 2026-11-17
**결정자**: AI 위임 (ADR-0315 슬라이스 2 · Jev `choice` p=0.91 conf 0.86)
**우선순위**: P1 (구조 · 진행)

## 컨텍스트 (Context)

ADR-0315 는 "런은 캠페인"을 정하고 슬라이스 2 를 **캠페인 골격**(`missionsCompleted`
카운트 + 미션 연쇄 + `liberation` 개방)으로 남겼다. 그때 실측된 문제:

- `missionsCompleted` 가 **하드코딩 1** 이었다(`state_actions_phases.ts`). 그래서
  `resolveEnding` 의 `missionsCompleted >= 3` 분기 — `liberation` 엔딩 — 이 **도달 불가**였다.
- 런은 여전히 **미션 하나**였다: 마지막 노드의 전리품에서 ENTER 를 누르면 곧바로 엔딩.

그리고 구현하려니 **ADR-0314 와 부딪힌다.** ADR-0314 는 `control`(부) 분기의 hp 게이트를
지우면서 **2330개 엔딩을 측정**했는데, 그 측정의 전제는 **런 = 미션 하나**였다. 캠페인은 그
전제를 바꾼다: 3미션을 완주하면 크레딧이 훨씬 많이 쌓인다(실측: g1 계약 하나가 **4575cr**).

## 고려한 옵션

### Option A: 완주(liberation)가 부(control)보다 먼저 (채택)
- **설명**: `resolveEnding` 에서 `missionsCompleted >= 3` 를 `credits > 5000` **앞으로** 옮긴다.
- **장점**: 캠페인의 절정이 **캠페인의 엔딩**이 된다. "계약을 끝냈다"가 "돈을 벌었다"보다
  런에 대해 더 많이 말한다. `control` 은 **짧고 부유한 런**의 엔딩으로 남는다(여전히 도달 가능).
- **단점**: ADR-0314 의 **측정 결과를 다른 분포에 적용**하게 된다 → 새 ADR 이 필요하다(이 문서).
- **Jev**: p=0.91 · conf 0.86.

### Option B: 순서를 두고 `control` 임계값을 올린다 (기각, p=0.08)
- **설명**: `credits > 5000` 을 캠페인 기준(예: 12000)으로 올린다.
- **단점**: 임계값이 **캠페인 길이에 묶인다.** 계약 길이를 바꾸면 밸런스가 조용히 깨진다.

### Option C: 순서를 두고 `control` 을 절정으로 받아들인다 (기각, p=0.01)
- **설명**: 3미션 완주자는 대개 부자이므로 `control` 이 뜬다.
- **단점**: 계약을 끝낸 거의 모든 런이 **"너는 부자가 됐다"** 로 끝난다. 캠페인의 보상이 없다.

### 계약의 모양 (별도 결정)

| | 선택 | 이유 |
|---|---|---|
| 길이 | **3미션** | `resolveEnding` 의 문턱이 `>= 3` 이다. 짧으면 절대 못 열고, 길면 늦게 온다 |
| 구성 | **고른 미션의 arc, 등급 오름차순** | arc 가 곧 계약의 이야기다(ADR-0316 이 미션마다 그 arc 의 서사를 브리핑한다). 등급 순서라 연쇄가 튀지 않는다 |
| 넘침 | **arc 를 감아 채운다** | 계약이 항상 채워진다. Far Grid 는 별도 유니버스라 제외(ADR-0213) |
| 미션 사이 | **HP 리셋 · 크레딧·덱·고유 이월** | Q3(HP 리셋) · ADR-0314(크레딧이 조건이려면 쌓여야 한다) · ADR-0303/0311(고유는 캠페인당 1장) |

## 결정 (Decision)

1. **런은 계약(contract)이다.** 고른 미션의 arc 에서 **3미션**을 등급 오름차순으로 연쇄한다.
2. **미션을 끝내면 다음 다리(leg)가 시작된다** — 엔딩이 아니라. 마지막 다리를 끝내야 엔딩이다.
3. **`missionsCompleted` 는 실제 개수다**(`campaign.completed + 1`). 계약 없는 런은 1 그대로다.
4. **완주가 부보다 먼저 온다**(Option A). `missionsCompleted >= 3` → `liberation`,
   `credits > 5000` → `control`. `hpPct <= 0`(sacrifice)는 여전히 둘보다 앞이다.
5. **계약은 저장된다** — 미션 **id 만**(슬롯은 레시피라는 관례). 복원은 카탈로그로 다리를
   다시 세우고, 저장된 미션과 다리가 어긋나면 **계약을 버리고 단일 미션으로** 되돌린다.
6. **다리 전환은 비트로 말한다** — 픽서가 다음 작업을 넘긴다(ADR-0316 의 브리핑을 그대로 쓴다).
   조용한 리로드가 아니라 이야기의 한 마디다.

## 결과 (Consequences)

- **바뀌는 것**: 계약이 있는 런은 미션 3개를 잇달아 플레이한다. 엔딩 화면은 계약을 끝낸
  런에서만 나오므로 **항상 `liberation`** 이다(실측: trace 가 `arc1_first_blood` 로 끝났다).
- **안 바뀌는 것**: **계약이 없는 런은 그대로다.** 테스트 픽스처·구버전 세이브·미션 단위
  하네스는 `campaign` 이 없어 이전과 같은 경로를 탄다 — 결정적 곡선이 **byte-identical** 인
  이유다(밸런스 `100/100/100/98.9/83.9/32.3` · 생존 `100/97.1/75.9/51.4/26.9/32.3`).
- **ADR-0314 와의 관계**: `control` 의 **조건**은 그대로다(`credits > 5000`, hp 게이트 없음).
  바뀐 것은 **분기 순서**이고, 그 이유는 ADR-0314 의 측정이 단일 미션 분포였다는 것이다.
- **미해결로 남기는 것**: 캠페인 기준 밸런스(ADR-0315 (d)) — 하네스가 미션 단위라
  "N미션 생존율"이 아직 없다. g6 고유 누적(ADR-0315 (c))도 그대로다.

## 다리 사이의 advance (2026-11-17 — ADR-0315 Q3 의 배선)

ADR-0315 Q3 는 *"미션 사이 회복은 전리품(prep)이 담당한다"* 고 적었지만 **배선이 없었다.**
그리고 구현하며 **버그를 찾았다**: `startNextLeg` 가 `makeInitialState` 를 다시 부르므로
**런 전 advance 의 `maxHp`·실드가 첫 다리 전환에서 사라졌다**(HP 는 만피로 리셋되므로 회복할 것도 없었다).
즉 게임의 다리 2·3 은 **advance 가 아예 없었고**, 하네스는 다리마다 advance 를 준다고 가정하고 있었다 —
**게임이 측정보다 어려웠다.**

```
미션 선택 → 브리핑 → [prep] → 1다리 → [CONTRACT 1/3 · DONE 카드 → CONTRACT 2/3 카드]
   → [다리 사이 advance] → 2다리 → … → 3다리 → 엔딩
```

- **advance 는 다리마다**(런 전 1회 + 다리 전환 2회) — ADR-0283 의 화면을 **그대로** 쓴다
  (`renderPrep` + `PREP_OPTIONS` + `prepGrantFor`), 금액이 `applyPrep` 과 어긋날 수 없다.
- **화면 순서**: 브리핑 카드가 먼저(카드가 화면을 소유), 그다음 advance. 카드는 큐로 두 장이 이어진다.
- **ESC 는 advance 를 건너뛴다**(쓰지 않고 잭인). 강제하지 않는다.
- `screen: "contract_prep"` 는 **런 중에만** 존재하므로 `SCREENS_WITH_INPUT`(state===null 경로)에는 넣지 않았다.
- **드라이버 3곳을 고쳤다**(소크 · story trace · `run_end_save`): 새 화면이 키를 먹으므로
  그대로 두면 소크가 **가짜 freeze** 를 보고한다(ADR-0273/0275 함정의 재확인).
- **하네스와 게임이 이제 일치**한다 — 기준선(완주 30.3%)이 게임의 실제 난이도가 됐다.

## 측정 — 캠페인 기준선 (2026-11-17, `npm run campaign`)

`npm run campaign`(신규 하네스, `scripts/campaign_survival.ts`) — **게임과 같은 계약**을
(`contractFor`) **게임과 같은 이월**로(`startNextLeg`: 크레딧·덱·고유) 3다리 플레이.
64시드 × 33 시작 미션 · `cards best` · `loot value`.

| | 이월 ON (게임) | 이월 OFF (`--fresh`) |
|---|---:|---:|
| leg 1 완주 | 57.4% (1212/2112) | 57.4% |
| leg 2 (조건부) | 64.6% (783/1212) | 62.3% |
| leg 3 (조건부) | 81.6% (639/783) | 80.0% |
| **계약 완주** | **30.3%** (639/2112) | **28.6%** |
| 완주 시 평균 크레딧 | **6536** | 3731 |
| 구 순서라면 `control` 이었을 것 | **100%** (639/639) | **3.0%** |

**시작 등급별 계약 완주**: g1 **100.0** · g2 **81.9** · g3 **41.7** · g4 **2.5** · g5 **3.0** · g6 **17.7**
(`--fresh`: g1 100.0 · g2 81.6 · g3 41.5 · g4 2.9 · g5 1.6 · g6 **3.6**)

**읽는 법 (실측이 말하는 것)**:
1. **ADR-0318 의 분기 순서는 필수였다 — 이월 때문에.** 이월하면 완주 계약의 **100%** 가 구 순서에서
   `control` 이었다(평균 6536cr). 이월하지 않으면 **3.0%** 뿐이다. 즉 "완주가 부보다 먼저"는
   **캠페인이 크레딧을 이월하기 때문에** 필요한 규칙이다.
2. **이월의 값**: 계약 완주 **+1.7pp**(30.3 vs 28.6) — 작다(ADR-0315 의 "덱은 자라지 않는다"와 일치).
   그런데 **g6 에서는 +14.1pp**(17.7 vs 3.6) — **고유 누적**이 만드는 차이다(ADR-0315 의 g6 +32.3pp 와 같은 뿌리).
3. **g4·g5 에서 계약을 시작하면 사실상 끝난다**(2.5 · 3.0%). g1~g3 은 100 · 81.9 · 41.7%.
   미션 단위 곡선은 g4 51.4 · g5 26.9 였으므로, **3연쇄가 그 값을 2~3% 로 만든다**.
4. **다리별 비율은 조건부**다(그 다리에 도달한 계약만 분모) — 뒤 다리가 높아 보이는 것은
   **생존자 편향**이지 난이도가 내려가서가 아니다. 무조건부 숫자는 **계약 완주율**이다.

## 열린 질문

- **(a) 미션 사이의 prep.** ✅ **닫힘(2026-11-17)**: 다리 사이에 **advance 화면**이 생겼다
  (`screen: "contract_prep"`). 아래 "다리 사이의 advance" 참조.
- **(b) 계약의 선택.** 지금은 **고른 미션의 arc** 가 계약을 정한다(미션 선택 화면이 곧 계약 선택).
  arc 를 직접 고르는 화면은 ADR-0315 의 "계약(arc)"을 더 정직하게 만든다.
- **(c) 캠페인 밸런스 기준선.** ✅ **닫힘(2026-11-17)**: `npm run campaign` 이 생겼고 위 기준선을
  기록했다. 남은 것은 **기준선을 어디에 둘지**(목표치) — 지금은 측정만 한다.
- **(d) 계약 길이의 가변성.** 3 은 리졸버의 문턱에서 온 숫자다. 길이를 플레이어나 arc 가
  정하게 되면 문턱도 함께 움직여야 한다.
- **(e) g4·g5 에서 시작한 계약이 2.5% · 3.0% 로 붕괴한다.** ✅ **닫힘(2026-11-17, 위임 결정 —
  난이도는 받아들이고 미션 목록이 계약을 말한다)**
  미션 단위로는 g4 **51.4%** 인데, 3연쇄가 그것을 **2.5%** 로 만든다. 원인은 **연쇄**이지 한 번의
  어려운 싸움이 아니다. *(아래 측정이 이 문단의 "등급 오름차순 에스컬레이션" 설명을 반박했다 —
  등급이 아니라 **등급 안의 난이도 분포**가 원인이다. 원문은 기록으로 남긴다.)*
  - **선택지**: ⑴ **그대로 둔다**(미션 목록이 등급을 보여주므로 g4 계약은 의도적 도박) ⑵ **뒤 다리를
    시작 등급 대에 묶는다**(에스컬레이션을 포기, g4 계약이 ~13% 로 오른다) ⑶ 계약 길이를 등급에
    따라 줄인다(문턱이 `>= 3` 이라 liberation 이 막힌다 — (d) 와 충돌).
  - **Jev `choice`**: ⑵ **p=0.63 · confidence 0.44** → 자동 적용하지 않고 표면화했다(추론이 아니라 취향).
  - **측정이 위 문장의 두 가지를 반박했다**(2026-11-17, 하네스 다리별 측정 256 시드):
    1. **"g4 시작은 g4→g4·5→g5 로 에스컬레이션한다"는 사실이 아니다.** g4 시작 7개는 **전부
       `4→4→4`** 이고, 시작 등급을 넘어서는 계약은 **33개 중 6개**뿐이다(`sense_net_tip` g3 →
       `3·3·5`, `final_choice` g5 → `5·6·6` 등). 그래서 ⑵("뒤 다리를 대에 묶기")는 **g4·g5 의
       붕괴를 고치지 못한다** — 원인이 등급 구성이 아니다.
    2. **"g4 미션 하나는 동전 던지기(51.4%)"도 아니다.** 시작 등급별 다리 완주율은
       **g4 `49.1% → 17.7% → 28.2%`**(곱 = 2.5%), **g5 `26.9% → 32.9% → 33.3%`** 로,
       **다리마다 3배씩 다르다.** 원인은 **(f)**: g4 미션의 **솔로 완주율이 1.6% ~ 100%** 로
       갈리기 때문이다(`mollys_razor`·`vegas_stakeout` 100%, `sally_returns_arc3` 99.2% vs
       `ta_heist` 1.6%, `neuromancer_whisper` 2.3%, `black_ice_dream` 10.2%). 미션의 맵과 조우
       ICE 는 **`matrix_seed` 로 고정**되므로(같은 미션 = 항상 같은 맵) 등급 평균 **51.4% 는
       1.6% 와 100% 의 평균**이다. 3연쇄는 **넓은 대역에서 세 번 뽑는 것**이고, 생존자 가중으로
       **2번째 다리가 가장 어려워진다**(쉬운 미션이 1다리일 때 그 뒤에 어려운 미션이 온다).
  - **결정(위임, 2026-11-17)**: ⑴ **난이도는 받아들인다** — 붕괴는 **연쇄의 곱**이지 한 번의 어려운
    싸움이 아니고, 등급 구성의 버그도 아니다. ⑵ 대신 **선택의 의미를 화면이 말한다**(오너 원칙:
    감 못 잡는 선택을 줄인다): 미션 목록이 `CONTRACT: 3 missions · T1→T1→T2` 를 보여준다. 이제
    **2.5% 계약이 51% 미션처럼 보이지 않는다.** ⑶ **(f) 는 오너 몫으로 남긴다** — 등급 재부여는
    밸런스 수치라 AI 가 임의로 바꾸지 않는다.
  - 하네스는 이 문장을 **출력에 그대로 인쇄**하므로, 목표치를 "의도"로 오해하지 않게 한다.
- **(f) 등급이 난이도 대역이 아니다 (2026-11-17 실측 — 오너 결정 필요).** 같은 g4 인데 미션별 솔로
  완주율이 **1.6%(`ta_heist`) ~ 100%(`mollys_razor`)** 로 갈린다. 미션의 맵·조우 ICE 는
  **`matrix_seed` 로 고정**되므로(같은 미션 = 같은 맵) 난이도는 **등급이 아니라 맵 시드의 추첨**에
  가깝다. 기록된 미션 단위 곡선(g4 51.4%)은 이 분포의 **평균**이라 대표성이 없다 — g4 계약이
  2.5% 인 것도, g3(41.7%)와 g5(3.0%) 사이가 10배 벌어진 것도 여기서 나온다.
  - **재조정 후보(오너 몫)**: ⑴ 미션 재등급(`ta_heist`·`neuromancer_whisper`·`black_ice_dream`
    이 g4 에는 너무 어렵다) ⑵ `matrix_seed` 재추첨으로 극단 맵 제거 ⑶ 하네스 정책 아티팩트인지
    확인(고정 맵 + 단일 정책이면 "불가능"이 정책의 한계일 수 있다).
  - **AI 는 측정만 한다** — 밸런스 수치는 오너 영역. 이 항목은 **열린 채로** 남긴다.
