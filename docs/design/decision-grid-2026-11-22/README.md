# Decision grid — ADR-0339 (g4) × ADR-0341 (gear vs ICE) · 2026-11-22

**왜 묶었나**: 두 ADR의 레버가 **같은 두 배열**(`ENCOUNTER_HP_BY_GRADE`,
`ENCOUNTER_DMG_BONUS_PCT_BY_GRADE`)에 쓰고, 어느 쪽이든 `balance.golden` ·
`gear.golden` 이 이동한다. 따로 결정하면 **골든을 두 번 재기록**한다.

**어떻게**: `web/scripts/decision_grid.py` — `tune_curve.py` /
`search_curve_constrained.py` 와 같은 규약(셀 사이에 소스를 패치하고 probe를 돌린 뒤
`finally` 에서 복원). 소스에 override 훅을 남기지 않는다(커밋되는 값이 곧 설정).

```
cd web
python3 scripts/decision_grid.py                  # 그리드 + 복원 + 표
python3 scripts/decision_grid.py --only "R g4=125"  # 한 셀만
```

## 1차 — g4 damage bonus (ADR-0339 이 지목한 레버) 는 약하다

g4 HP 는 95 그대로, dmg bonus 만 0 / +10 / +20.

| g4 dmg | 캠페인 g3 | 캠페인 g4 | T6 g5 | T6 g6 | g3≥g4 |
|---|---|---|---|---|---|
| +0 | 50.0 | 64.3 | 94.6 | 99.0 | NO |
| +10 | 50.0 | 65.0 | 94.6 | 99.0 | NO |
| +20 | 50.0 | 60.0 | 94.6 | 99.0 | NO |

→ **+20 까지 올려도 g4 는 64.3 → 60.0, g3 은 50.0 불변.** ADR-0339 의 "남은 손잡이
= dmg bonus" 가정은 틀렸다. 자동공격 공식이 계단 함수라 이 구간에서 g4 를 움직이지 못한다.

## 대가 (오너가 알아야 하는 것)

1. **bare 후반이 내려간다** — g5 28.5 → 8.7 · g6 43.8 → 18.8 (GRADE_TARGETS 25/30 아래).
   ADR-0229 이후 이 목표는 "추구할 목표"가 아니라 기준선이므로 **신호**로 읽는다.
2. **캠페인 g6 이 0%** — 캠페인 하네스는 **장비를 착용하지 않는다**(bare 전용). 장비를
   전제로 난이도를 올리면 bare 러너는 g6 계약을 끝낼 수 없다. 곧 `campaign_survival.ts`
   에 **장비 로드아웃 옵션**이 필요하다 — 없으면 `CONTRACT_TARGETS` 재기록이 "존재하지 않는
   러너"를 기록하게 된다.
3. **T6 g5 72.7 은 밴드 상단**(57~73) 근처다. 140 으로 올리면 73.3 으로 오히려 나빠진다
   (정책 비선형). 더 낮추려면 g5 band 자체를 손대야 한다.
