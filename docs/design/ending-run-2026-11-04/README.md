## 관측된 전환 체인

```
mission_select → matrix → encounter(도착) → combat/approach → combat
   → loot/victory → (카드 획득) → matrix → … → boss → loot → ending → title
```

각 전환은 **입력 한 번**으로 이어졌고, 화면이 약속한 키가 실제로 동작했다(ADR-0251 §5 준수).
패스(COST 상한)는 이 런에서 발동하지 않았다(최종 COST 59).

## 서사 어색함 5건 (측정 근거 포함)

### 1. 한 런의 모든 전투가 **같은 ICE**
로그의 모든 조우가 `Yakuza Enforcer 165/165` — 보스 노드(`core-deep`)도 동일.
`missionIce` 가 미션당 ICE **하나**를 고르고 `encounterRoster` 가 **그 하나를 모든 조우에 복제**한다.
→ 28노드를 지나도 적이 한 종류. **보스가 서사적으로 구별되지 않는다.**

### 2. 플레이어가 **관객**이 된다 (Dixie 스케일링)
```
[4]  >>> Dixie attacks: 11 dmg      ← combo 1
[19] >>> Dixie attacks: 35 dmg      ← combo 9
[41] >>> Dixie attacks: 68 dmg
[52] >>> Dixie attacks: 80 dmg
```
`Dixie 데미지 = 8 + playerCombo × 3` 인데 **콤보가 런 내내 누적**된다. 같은 시점 플레이어 카드는
`Strike → 6 dmg` · `Boost → 4 dmg` · `Kraken → 17 dmg`. 후반 전투의 **피해 대부분을 동료가 낸다.**

### 3. 엔딩이 **이 런을 되돌아보지 않는다**
`ENDING / ARC 4` · `LIBERATION FRONT` · `The AIs are free. What have you done?` — 2줄.
`EndingContext` 는 hp·credits·missionsCompleted·faction·choices 를 갖고 있지만 **문구에 반영되지 않는다.**
미션명·획득 크레딧·죽음 수·선택이 엔딩에 남지 않는다.

### 4. 절차 문구의 **동일 반복**
노드마다 같은 문장이 그대로 나온다:
`"Travel blocked. BREACH: fight. BYPASS: 60 COST (once per run). JACK OUT: abandon run."`
`"Entering mid... (1 ICE)"` · `"Moved to surface — ↑↓ picks the next route"` · `"Choose an adjacent route — healed to 100/100"`.
기능적으로는 정확하지만 **서사적 이정표가 없다**(보스 접근, 구역 전환, 마지막 노드).

### 5. 회복 문구가 사실상 무의미
HP 100 에서 `healed to 100/100`. 회복이 실제로 아무것도 하지 않은 경우에도 "적용됨"이라고 말한다.

## (a) 밸런스 심에 턴 패스 모델링 — 결과

`balance_sim` 이 상한에서 `use_program` 을 반복하던 것을 **실제 게임과 동일하게** `confirm`(턴 패스)로
바꿨다(`everyProgramBlocked` 사용, 컨트롤러가 보내는 그 액션).

**곡선은 byte-identical** 했다:
```
grade 1..6  win-rate 100.0 / 100.0 / 81.4 / 42.6 / 36.6 / 0.0   (전후 동일)
```

**왜**: 심의 단위는 **전투 1회**다. COST 는 **런 전체**에서 누적되는 예산이라(브라우저 완주에서 최종 59,
상한 도달은 13/159 런) **전투 1회 시뮬레이션은 상한 근처에 가지 않는다**(헛바퀴 0.0%).
즉 **D1 의 밸런스 효과는 이 심으로 측정 불가**이고, 그것을 측정하려면 **런 단위 시뮬레이터**가 필요하다.

## (e) 근거 — 패스는 "무료 승리 버튼"이 될 수 있다

상한에서는 카드를 못 쓰므로 **패스만 가능**하고, 패스는 턴을 넘겨 **Dixie 를 계속 공격시킨다**.
Dixie 데미지가 콤보에 비례해 80~98 까지 오르므로, **상한에 도달한 뒤 가만히 있어도 이긴다.**
전수조사에서 **상한 도달 13런이 전부 완주**한 것이 그 증거다.

→ 패스 자체에 비용을 붙이는 것보다, **Dixie 콤보 스케일링을 전투 단위로 리셋하거나 상한을 두는 것**이
원인에 가깝다(패스는 그저 "가만히 있기"를 가능하게 할 뿐).
