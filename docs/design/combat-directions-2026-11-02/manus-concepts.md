# 축 1 — 프로그램의 이해와 선택

전제: 아래 안들은 모두 `HAND: [id 앞 4글자]`를 **이름·비용·효과·대상·예측 결과가 있는 선택 가능한 프로그램 UI**로 바꾼다. 숫자키 즉시 실행은 폐기하거나, 최소한 `선택 → 확인` 2단계로 바꾼다. 비용은 에너지가 아니라 **알람 COST 증가량**으로 표시한다.

## 1안 — `PROGRAM INSPECT`: 손패를 고르면 옆에서 해독되는 방식

### 한 문장 요약

손패를 커서로 고르면 오른쪽 상세 패널에서 프로그램의 효과와 현재 타겟 기준 결과를 해독하고, 확인해야 실행한다.

### 무엇이 달라지는가

- 손패에 `name`, `cost`, `role`, `target`, `effect`, `damage`, `aoe`를 표시한다.
- `↑↓`로 프로그램을 선택하고 `ENTER`로 실행한다.
- 실행 전 `ESC`로 취소할 수 있다.
- `Tab`으로 살아있는 ICE 타겟을 순환한다.
- 피해량은 단일값이 아니라 현재 전투 규칙을 반영한 예상 범위로 표시한다.
- 킬 가능성은 다음처럼 표시한다.
  - `KILL: CERTAIN`
  - `KILL: POSSIBLE`
  - `KILL: NO`
  - 계산할 수 없는 경우 `KILL: UNKNOWN`
- AoE는 `TARGET: ALL ICE`와 범위 기호로 표시한다.
- 상태 글리프 하단에 짧은 범례를 고정한다.

### ASCII 목업

```text
 MATRIX // BREACH NODE                         T07   ALARM COST 38/100
┌──────────────────────────────────────────────┬─────────────────────────┐
│                                              │ TARGET                  │
│   ICE FIELD                                  │ > 1. WRAITH [B2]        │
│                                              │    HP [####....] 42/80  │
│       > [1] WRAITH                           │    2. SENTRY [ST] 18/30 │
│         [2] SENTRY                           │                         │
│         [3] NULL-SPIDER [DEAD]               │ STATUS LEGEND            │
│                                              │ B2 = BURN, 2 turns      │
│       YOU  HP [########..] 10/12             │ ST = STUN, 1 turn       │
│                                              │ SH = SHIELD              │
├──────────────────────────────────────────────┼─────────────────────────┤
│ PROGRAM INSPECT                             │ SELECTED: ARC_LANCE      │
│                                              │ ROLE     STRIKE          │
│ > 1 [ARC_LANCE]                              │ COST     +12 ALARM       │
│   2 [PATCH]                                  │ TARGET   1 ICE            │
│   3 [SPLIT]                                  │ EFFECT   damage + burn   │
│   4 [GHOST]                                  │ DAMAGE   17–24 estimated │
│                                              │ STATUS   BURN 2 turns    │
│                                              │ AFTER    COST 50/100     │
│                                              │ KILL     POSSIBLE        │
│                                              │                          │
│ [↑↓] SELECT   [TAB] TARGET   [ENTER] EXECUTE │ [ESC] CANCEL             │
└──────────────────────────────────────────────┴─────────────────────────┘
 HAND: 1 ARC_LANCE  2 PATCH  3 SPLIT  4 GHOST
 MSG: ARC_LANCE is loaded. No packet sent.
```

### 첫 30분의 느낌

첫 전투부터 “무슨 카드인지 모르고 눌러보는” 느낌이 줄어든다. 플레이어는 `이번 공격이 죽일 수 있는가`, `알람을 얼마나 올리는가`, `상태 부여와 직접 피해 중 무엇이 필요한가`를 짧게 판단하게 된다.

### 가장 큰 실패 시나리오

상세 정보가 한 화면에 너무 많이 들어가서, 해킹 전투가 아니라 작은 엑셀 표를 읽는 느낌이 될 수 있다. 특히 40×60에서 우선순위가 무너지면 실패한다.

### 하지 말아야 할 것

- 모든 내부 계산식과 보정값을 공개하지 않는다.
- 피해 예상치를 `17.38`처럼 정밀하게 표시하지 않는다.
- 설명 문장을 길게 늘려 HUD를 카드 도감처럼 만들지 않는다.
- `KILL: POSSIBLE`을 확정 처치처럼 오해하게 만들지 않는다.

### 기존 시스템 재사용 지점

- 기존 `Tab` 타겟 순환.
- 기존 메시지 채널의 실행 전 미리보기 문구와 실행 후 `"{name} → {damage} dmg..."`.
- 기존 `attack`, `heavy_attack`, `ice_hit`, `critical_hit` VFX.
- 기존 `combat_skill_strike`, `combat_skill_burst`, `combat_skill_guard`, `combat_skill_support` 음향.
- 기존 상태 글리프와 `[B2]` 표기를 범례와 함께 재사용.

## 2안 — `CARD RAIL`: 하단 손패를 실제 카드 레일처럼 만드는 방식

### 한 문장 요약

전투 화면 하단을 손패 전용 레일로 만들고, 선택된 프로그램만 위로 확장되어 상세 정보와 실행 키를 보여준다.

### 무엇이 달라지는가

- 손패의 위치를 유지하므로 기존 플레이어 습관을 덜 깨뜨린다.
- 선택된 카드만 2~4행 높이로 확장한다.
- 카드마다 항상 보이는 최소 정보는 `이름 / 비용 / 역할 / 대상`이다.
- 상세 설명은 선택된 카드에만 표시한다.
- 터치 버튼 `1.abcd`도 이름과 비용을 포함한다.
- `ENTER` 실행, `ESC` 취소를 추가한다.

### ASCII 목업

```text
 MATRIX // NODE 04                              T07   COST 38/100
┌──────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│                 +-------------------+                                    │
│                 | > 1 WRAITH        |                                    │
│                 |   HP [####....]   |                                    │
│                 +-------------------+                                    │
│                                                                            │
│ YOU HP [########..] 10/12       ICE: 1 WRAITH  2 SENTRY                  │
│                                                                            │
├──────────────────────────────────────────────────────────────────────────┤
│ HAND / CHOOSE PROGRAM                                                     │
│                                                                            │
│ ┌──────────────────┐  ┌──────────────┐  ┌──────────────┐  ┌─────────────┐ │
│ │>1 ARC_LANCE      │  │ 2 PATCH     │  │ 3 SPLIT     │  │ 4 GHOST     │ │
│ │  STRIKE  +12     │  │  SUPPORT +6 │  │ BURST  +18  │  │ EVADE  +9   │ │
│ │  1 ICE / 17–24   │  │ YOU / +4 HP │  │ ALL / 8–13   │  │ SELF / 1T  │ │
│ ├──────────────────┤  └──────────────┘  └──────────────┘  └─────────────┘ │
│ │ ARC_LANCE: pierce packet. Applies BURN [B2].                            │
│ │ TARGET > 1 WRAITH   AFTER COST 50/100   KILL: POSSIBLE                 │
│ └──────────────────────────────────────────────────────────────────────────┘
│ [←→] CHOOSE  [TAB] TARGET  [ENTER] EXECUTE  [ESC] CANCEL                 │
│ MSG: Awaiting confirmation.                                                │
└──────────────────────────────────────────────────────────────────────────┘
```

### 첫 30분의 느낌

기존 `HAND:` 위치를 보존하기 때문에 적응이 빠르다. 손패가 단순한 슬롯 목록이 아니라 “지금 쓸 도구를 고르는 작업대”처럼 느껴진다.

### 가장 큰 실패 시나리오

카드가 많아지거나 이름이 길어지면 가로 폭이 먼저 무너진다. 80열에서만 보기 좋고 40열에서는 카드가 지나치게 축약될 가능성이 크다.

### 하지 말아야 할 것

- 카드마다 긴 flavor text를 넣지 않는다.
- 카드 테두리와 장식에 공간을 과소비하지 않는다.
- 실제 카드 게임처럼 드래그, 손패 재배열, 덱 확대까지 확장하지 않는다.
- 카드 색만으로 역할을 표현하지 않는다. 역할명과 글리프를 함께 사용한다.

### 기존 시스템 재사용 지점

- 현재 손패 슬롯과 터치 버튼의 위치 및 입력 연결.
- 기존 숫자키를 “선택”에 재매핑하고 `ENTER`에서 실행.
- 기존 떠오르는 피해 숫자와 스킬별 색상.
- 기존 `shield`, `heal`, `buff`, `debuff`, `stun`, `regen`, `detect` VFX를 카드 효과와 연결.
- 기존 최신 메시지 1줄을 확인 대기 상태로 재사용.

## 3안 — `TARGET FIRST`: 먼저 ICE를 고르고, 가능한 프로그램만 보여주는 방식

### 한 문장 요약

플레이어가 먼저 공격할 ICE를 선택하면 손패가 해당 타겟에 유효한 프로그램 중심으로 정리된다.

### 무엇이 달라지는가

- `Tab`으로 타겟을 먼저 고른다.
- 선택된 ICE 옆에 현재 타겟의 HP, 상태, 예상 피해, 킬 가능성을 띄운다.
- 손패는 `유효`, `조건부`, `현재 사용 불가` 세 그룹으로 구분한다.
- AoE 프로그램은 `ALL ICE` 그룹에 별도 표시한다.
- 단일 타겟과 AoE의 차이가 행동 전에 명확해진다.
- 타겟이 바뀌면 예상값도 즉시 갱신된다.

### ASCII 목업

```text
 MATRIX // TARGET LOCK                              T07  COST 38/100
┌───────────────────────────────┬──────────────────────────────────────────┐
│ ICE ROSTER                     │ TARGET ANALYSIS                         │
│                               │ > 1 WRAITH  HP 42/80  [B2]              │
│ > 1 WRAITH  [B2]  [####....] │   EST. DAMAGE: 17–24                    │
│   2 SENTRY   [ST]  [##......] │   AFTER HIT: 18–25 HP                   │
│   3 NULL-SPIDER [DEAD]        │   KILL: POSSIBLE                        │
│                               │   EFFECTS: BURN 2T                      │
│ YOU HP [########..] 10/12     │                                          │
├───────────────────────────────┼──────────────────────────────────────────┤
│ AVAILABLE PROGRAMS             │ TARGET LEGEND                           │
│ > 1 ARC_LANCE  STRIKE +12     │ 1 = single ICE                         │
│     17–24 dmg / BURN [B2]     │ ALL = all living ICE                    │
│     [ENTER] KILL POSSIBLE     │ B2 = BURN, 2 turns                      │
│   2 PATCH      SUPPORT +6     │                                          │
│     target: YOU / +4 HP       │                                          │
│   3 SPLIT      BURST +18      │ ALL / 8–13 each / +18 COST               │
│   4 GHOST      EVADE +9       │                                          │
│                               │ [TAB] NEXT ICE  [ENTER] PICK PROGRAM     │
├───────────────────────────────┴──────────────────────────────────────────┤
│ HAND: [1 ARC_LANCE] [2 PATCH] [3 SPLIT] [4 GHOST]   [ESC] CANCEL          │
│ MSG: Target locked: WRAITH.                                                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 첫 30분의 느낌

전투의 질문이 “어떤 카드를 누르지?”에서 “이 적을 지금 끝낼 것인가, 다른 적을 약화할 것인가?”로 이동한다. 타겟과 프로그램의 관계가 명확해져 기존 `Tab` 시스템의 존재감도 커진다.

### 가장 큰 실패 시나리오

플레이어가 항상 가장 낮은 HP의 ICE를 먼저 고르는 것이 정답이 되면, 타겟 선택은 형식적인 단계로 전락한다.

### 하지 말아야 할 것

- 프로그램을 자동으로 추천하거나 최적 행동을 하나로 강조하지 않는다.
- 킬 가능성이 있다고 해서 항상 그 타겟을 우선하도록 유도하지 않는다.
- 타겟별 수치가 너무 많아 로스터보다 별도 분석 화면이 더 커지게 하지 않는다.
- 실제로 존재하지 않는 적 의도 정보를 임의로 추가하지 않는다.

### 기존 시스템 재사용 지점

- 현재 ICE 로스터의 `>` 타겟 표시.
- 기존 `Tab` 순환 로직.
- 기존 AoE 판정.
- 기존 피해 숫자, 피격 플래시, `ice_hit`, `player_hit`, `critical_hit`.
- 기존 실행 후 메시지 채널.

## 4안 — `COMMAND DECK`: 카드가 아니라 짧은 명령어를 해독하는 방식

### 한 문장 요약

손패는 프로그램 슬롯으로 유지하되, 선택 시 터미널 명령어와 결과 요약이 함께 나타나 콘솔 카우보이의 조작감을 강화한다.

### 무엇이 달라지는가

- 프로그램 이름과 함께 해석된 명령형 문구를 보여준다.
- 예: `ARC_LANCE` → `PIERCE WRAITH / +12 COST / 17–24 DMG`.
- 선택 후 `CONFIRM? [Y/N]`을 제공한다.
- `Y` 실행, `N` 또는 `ESC` 취소.
- 프로그램 설명은 한 줄짜리 동작 문장으로 제한한다.
- 역할은 `STRIKE`, `SUPPORT`, `CONTROL`, `DEFENSE`처럼 텍스트와 글리프로 병기한다.

### ASCII 목업

```text
 MATRIX // CONSOLE LINK                           T07  ALARM 38/100
┌──────────────────────────────────────────────────────────────────────────┐
│ ICE: >1 WRAITH [B2] HP [####....] 42/80     2 SENTRY [ST] 18/30          │
│ YOU: HP [########..] 10/12                  STATUS: —                    │
│                                                                            │
│ HAND                                                                     │
│ 1 ARC_LANCE   2 PATCH   3 SPLIT   4 GHOST                                │
│                                                                            │
│ > ARC_LANCE / STRIKE                                                     │
│   $ pierce --target WRAITH --burn 2                                      │
│   COST: +12 ALARM     AFTER: 50/100                                      │
│   RESULT: 17–24 DMG + BURN [B2]                                          │
│   KILL: POSSIBLE       TARGET: 1 ICE                                    │
│                                                                            │
│   CONFIRM PACKET?  [Y] SEND   [N] ABORT                                  │
│                                                                            │
│ STATUS GLYPHS: [B2] Burn / [ST] Stun / [SH] Shield                       │
│ [1–4] SELECT  [TAB] TARGET  [ENTER/Y] SEND  [ESC/N] ABORT                 │
│ MSG: Packet staged. No effect until confirmed.                            │
└──────────────────────────────────────────────────────────────────────────┘
```

### 첫 30분의 느낌

프로그램 사용이 전투 카드 조작보다 터미널 침투에 가깝게 느껴진다. 확인 단계가 명시적이라 실수로 알람을 올리는 불쾌감이 줄어든다.

### 가장 큰 실패 시나리오

매번 `Y`를 한 번 더 눌러야 해서 전투가 느려지고, 모든 프로그램이 같은 “명령어 스킨”으로 보여 실제 차이를 이해하는 데 도움이 되지 않을 수 있다.

### 하지 말아야 할 것

- 명령어 문법을 실제 입력 퍼즐로 만들지 않는다.
- 오타, 타이핑 속도, 명령어 암기를 요구하지 않는다.
- 확인 단계를 모든 사소한 효과에 강제해 전투 템포를 떨어뜨리지 않는다.
- 긴 로그를 늘려 최신 메시지 채널을 대체하지 않는다.

### 기존 시스템 재사용 지점

- 최신 메시지 1줄.
- 기존 프로그램 실행 이벤트와 비용 초과 메시지.
- `attack`, `heavy_attack`, `counter`, `lifesteal`, `dot` VFX.
- 미배선 `credit_spend`가 아니라, 프로그램 사용 자체에는 현재 규칙대로 알람 COST 표시만 사용한다. 크레딧과 혼동하지 않는다.

# 축 2 — 가시적 효과

전제: 기존 VFX는 입력을 막지 않는 순수 오버레이이므로, 아래 안들도 **연출과 조작 잠금을 분리**한다. 2초 시간 게이트는 적 공격의 타이밍이지 카드당 1회 공격 의도가 아니므로, 별도의 적 intent UI를 추가하는 것은 여기서 제안하지 않는다.

---

## 1안 — `EVENT GRAMMAR`: 모든 전투 이벤트를 같은 문법으로 보여주는 방식

### 한 문장 요약

모든 변화에 `발생 → 대상 → 결과 → 잔여 상태`라는 짧은 ASCII 연출 문법을 부여해, 기존 VFX를 더 촘촘하고 일관되게 연결한다.

### 무엇이 달라지는가

- 상태 부여: 대상 주변에 `+BURN [B2]`가 160~320ms 표시된다.
- 상태 만료: `BURN EXPIRED` 또는 `BURN -1`이 표시된 뒤 글리프가 사라진다.
- 회복: HP 바를 즉시 스냅하지 않고 짧은 단계 갱신으로 보간한다.
- 비용 증가: `COST +12`가 HUD에서 프로그램 위치 쪽으로 이동한다.
- 크레딧 획득·소비: `+25cr`, `-10cr`이 해당 메시지 위치에서 떠오른다.
- 루트 획득: `LOOT ACQUIRED`와 아이템 글리프가 짧게 남는다.
- 보스 페이즈: `PHASE SHIFT`가 800ms 동안 중앙에 표시된다.
- 같은 종류의 이벤트는 같은 글리프, 같은 위치, 같은 시간 규칙을 쓴다.

### ASCII 목업

```text
                 +-----------------------+
                 | > WRAITH              |
                 | HP [#####...] 51/80   |
                 |       ^               |
                 |   +BURN [B2]          |
                 +-------|---------------+
                         |
                    --→  *  21
                         |
YOU HP [########..] 10/12       COST 38/100
                              COST +12
                              +12 ALARM

FEED: ARC_LANCE → 21 dmg → WRAITH HP 51 → 30
      STATUS: BURN applied [2 turns]

[after 2 turns]
                 WRAITH
                 BURN EXPIRED
                 [B2] -> [—]

LEGEND: B2 Burn / ST Stun / SH Shield
```

### 첫 30분의 느낌

공격뿐 아니라 상태, 비용, 루트, 페이즈 변화에도 “무슨 일이 일어났다”는 감각이 생긴다. 기존 VFX가 단발 효과 목록이 아니라 전투의 문법으로 읽힌다.

### 가장 큰 실패 시나리오

이벤트가 겹칠 때 텍스트와 숫자가 서로 가려져, 오히려 피해량과 HP 변화가 덜 읽힐 수 있다.

### 하지 말아야 할 것

- 모든 이벤트를 화면 중앙에 띄우지 않는다.
- 상태 변화마다 화면 흔들림을 사용하지 않는다.
- 작은 수치 변화까지 모두 큰 배너로 만들지 않는다.
- 연출을 위해 입력을 잠그지 않는다.

### 기존 시스템 재사용 지점

- `status_apply` 렌더러를 실제 생성 경로에 연결.
- 기존 `attack`, `ice_hit`, `player_hit`, `critical_hit`.
- 기존 떠오르는 피해 숫자.
- 미배선 `heal`, `credit_gain`, `credit_spend`, `loot_drop`, `phase_change`, `death` 음원.
- 기존 메시지 채널은 상세 이벤트 기록이 아니라 최근 결과 요약으로 유지.

## 2안 — `COMBAT LEDGER`: 화면 하단에 최근 전투 결과를 누적하는 방식

### 한 문장 요약

화면 하단의 최신 메시지 1줄을 짧은 3줄 전투 원장으로 확장해, 빠른 VFX를 놓쳐도 결과를 복구할 수 있게 한다.

### 무엇이 달라지는가

- 최신 메시지 1줄을 최대 3줄의 짧은 원장으로 확장한다.
- 각 줄은 `행위자 → 대상 : 결과` 형식을 사용한다.
- 상태 부여와 만료를 별도 행으로 남긴다.
- 피해 숫자와 HP 바는 기존 VFX를 그대로 쓰되, 원장이 안정적인 확인 수단이 된다.
- 화면 흔들림과 플래시는 유지하되, 그 자체가 정보 전달의 유일한 수단이 되지 않게 한다.

### ASCII 목업

```text
 MATRIX // COMBAT                                 T07  COST 50/100
┌──────────────────────────────────────────────────────────────────────────┐
│ ICE ROSTER                                                                │
│ > 1 WRAITH [B2] [###.....] 30/80       2 SENTRY [ST] [##......] 18/30   │
│                                                                            │
│ YOU HP [########..] 10/12                                                │
│                                                                            │
│                 WRAITH                                                     │
│                  HIT! -21                                                  │
│                 floating: +BURN                                            │
│                                                                            │
├──────────────────────────────────────────────────────────────────────────┤
│ COMBAT LEDGER                                                             │
│ T07  ARC_LANCE  → WRAITH       21 dmg   HP 51→30                          │
│ T07  STATUS     → WRAITH       BURN +2T                                  │
│ T06  WRAITH     → YOU          blocked / no damage                        │
│                                                                            │
│ LEGEND: B2 Burn / ST Stun / SH Shield   [Tab] target  [1–4] program       │
└──────────────────────────────────────────────────────────────────────────┘
```

### 첫 30분의 느낌

기존 전투가 빠르게 지나가도 플레이어는 “내가 무엇을 했고 적이 무엇을 했는지” 다시 확인할 수 있다. 특히 상태 만료, 크레딧, 루트처럼 짧게 사라지는 이벤트가 덜 유실된다.

### 가장 큰 실패 시나리오

로그를 읽는 것이 실제 전투보다 중요해져서, 플레이어가 매 행동 후 하단 텍스트를 확인해야 하는 느낌이 날 수 있다.

### 하지 말아야 할 것

- 로그를 무한히 누적하지 않는다.
- 서사 문장이나 해킹 flavor text를 전투 원장에 넣지 않는다.
- 기존 메시지 채널과 별도 로그를 둘 다 길게 운영하지 않는다.
- 로그가 모든 VFX의 대체품이 되게 하지 않는다.

### 기존 시스템 재사용 지점

- 최신 메시지 채널의 데이터.
- 기존 실행 후 메시지 형식.
- 기존 `combat_hit`, `combat_block`, `damage`, `attack` 음향.
- 상태 부여·만료 이벤트를 새 원장 행으로 연결.
- 기존 HP 바와 변화 시 빨강·초록 플래시.

## 3안 — `SIGNAL BURST`: 중요한 이벤트만 짧고 강하게 강조하는 방식

### 한 문장 요약

모든 것을 애니메이션화하지 않고, 상태 부여·상태 만료·페이즈 전환·루트·죽음처럼 현재 피드백이 없는 사건만 강한 신호로 만든다.

### 무엇이 달라지는가

- 일반 공격은 현재의 투사체, 피격 플래시, 피해 숫자를 유지한다.
- 상태 부여만 `STATUS +` 형태의 짧은 burst를 추가한다.
- 상태 만료는 글리프가 사라지기 직전 `EXPIRED`를 표시한다.
- 보스 페이즈 전환은 `PHASE CHANGE`와 `phase_change` 사운드를 연결한다.
- 루트 획득은 `loot_drop` 사운드와 아이템 글리프 낙하를 사용한다.
- 죽음은 기존 `FLATLINE`을 유지하면서 `death` 음원을 연결한다.
- 크레딧은 작은 `+/-` 숫자만 표시해 전투를 방해하지 않는다.

### ASCII 목업

```text
                          [STATUS +]
                          BURN [B2]
                              |
                 +------------v------------+
                 | > WRAITH                |
                 | HP [###.....] 30/80     |
                 +-------------------------+

                 ... 320ms 후 ...

                          [EXPIRED]
                          BURN [—]

                 +-------------------------+
                 |      PHASE CHANGE       |
                 |      CORE ICE // 02     |
                 +-------------------------+

                    [DATA CACHE]  +25cr
                         \  loot_drop
```

### 첫 30분의 느낌

평소 화면은 조용하게 유지되면서도, 중요한 사건은 확실히 “발생했다”고 느껴진다. 네온 단말기 톤과도 잘 맞고, 기존 연출의 밀도를 무작정 높이지 않는다.

### 가장 큰 실패 시나리오

무엇이 “중요한 이벤트”인지 기준이 흔들리면 일부 상태는 눈에 띄고 일부는 조용해져 피드백 규칙이 불공평하게 느껴질 수 있다.

### 하지 말아야 할 것

- 모든 피해에 대형 배너를 붙이지 않는다.
- 상태 종류마다 전혀 다른 애니메이션 언어를 만들지 않는다.
- 페이즈 전환을 실제 보스 로직과 무관하게 장식용으로 재생하지 않는다.
- 루트·크레딧 획득 연출이 전투 승리보다 더 화려해지게 하지 않는다.

### 기존 시스템 재사용 지점

- 존재하지만 미생성인 `status_apply`.
- `boss_phase_transition` VFX.
- 미배선 `phase_change`, `loot_drop`, `credit_gain`, `credit_spend`, `death`.
- 기존 `ice_intro`, `ice_death`, `victory`, `defeat`.
- 기존 reduced-motion 규칙을 모든 burst에 적용.

## 4안 — `READABLE IMPACT`: HP와 자원 변화의 가시성을 우선하는 방식

### 한 문장 요약

새로운 장식보다 HP·알람 COST·상태·루트 수치가 스냅되지 않고 짧게 변화하도록 만들어, 전투 결과를 한눈에 읽게 한다.

### 무엇이 달라지는가

- 플레이어와 ICE HP 바를 즉시 최종값으로 바꾸지 않고 짧게 보간한다.
- 실제 피해 숫자는 기존처럼 떠오르되, 바의 감소가 한 박자 뒤따른다.
- 알람 COST도 `38 → 50`으로 짧게 증가 애니메이션을 준다.
- 회복은 녹색 증가 방향, 피해는 빨간 감소 방향을 사용한다.
- 상태 글리프는 부여 시 나타나고, 만료 시 짧게 깜빡인 뒤 사라진다.
- 크레딧과 루트는 획득 위치에서 HUD 방향으로 이동한다.
- reduced-motion에서는 보간을 제거하고 색·문자 변화만 유지한다.

### ASCII 목업

```text
BEFORE                          DURING                 AFTER
WRAITH HP [####....] 42/80      [###.....] 30/80       [###.....] 30/80
                                  ^^^ decrease

YOU HP [########..] 10/12       YOU HP [########..]    YOU HP [########..]
COST 38/100                      COST 44/100           COST 50/100
                                  +12 ALARM

                 --→  * 21
                 floating damage: -21

FEED: ARC_LANCE → WRAITH
      HP 42 → 30   COST 38 → 50
```

### 첫 30분의 느낌

공격이 실제로 “먹혔다”는 감각이 강해진다. 현재의 스냅식 HP 변화 때문에 놓치던 피해, 회복, 비용 상승이 시간 순서로 읽힌다.

### 가장 큰 실패 시나리오

보간 시간이 길거나 여러 효과가 연속으로 발생하면 화면이 계속 따라잡는 중처럼 보여, 2초 시간 게이트와 맞물려 반응이 느리게 느껴질 수 있다.

### 하지 말아야 할 것

- HP 보간을 실제 게임 시간이나 적 공격 게이트와 결합하지 않는다.
- 연출 중 입력을 지연시키지 않는다.
- 난수 피해의 내부 과정을 애니메이션으로 보여주지 않는다.
- 숫자 변화가 색 변화에만 의존하지 않게 한다.

### 기존 시스템 재사용 지점

- 기존 HP 12칸 바와 임계값 색.
- 기존 HP 변화 시 빨강·초록 행 플래시.
- 기존 떠오르는 피해 숫자.
- 기존 `heal` 음원과 현재 연결된 피해·피격 음원.
- 기존 2px 화면 흔들림은 플레이어 피격에만 제한적으로 유지.

## 축 1: `PROGRAM INSPECT`

## 축 2: `EVENT GRAMMAR` + 제한적인 `READABLE IMPACT`

### 이유

현재 가장 큰 문제는 연출의 부족보다 **행동 전에 프로그램의 의미를 알 수 없다는 것**이다. 이름, 비용, 역할, 대상, 예상 결과가 없으면 어떤 VFX를 추가해도 플레이어는 “왜 이런 결과가 나왔는가”를 이해하지 못한다.

`PROGRAM INSPECT`는 다음 네 가지를 한 화면에서 해결한다.

1. 프로그램을 고르는 행위가 명확해진다.
2. 타겟과 AoE 여부가 실행 전에 보인다.
3. 알람 COST 증가를 사전에 이해할 수 있다.
4. 피해량과 킬 가능성을 결과 예측으로 연결한다.

그 위에 `EVENT GRAMMAR`를 얹으면 `상태 부여`, `상태 만료`, `페이즈 변화`, `루트 획득`처럼 현재 아무 피드백이 없는 이벤트가 기존 투사체·피격 플래시·피해 숫자와 같은 언어 안으로 들어온다. HP와 COST 보간은 장식이 아니라 실제 변화의 가독성을 높이는 범위에서만 제한적으로 사용한다.

### 가장 큰 리스크

예상 피해와 킬 가능성을 너무 정확하게 표시하면, 플레이어가 해킹하는 느낌보다 계산기를 읽는 느낌을 받을 수 있다. 반대로 난수·방어·크리티컬을 모두 숨기면 미리보기가 신뢰를 잃는다. 따라서 정확한 내부 계산 공개가 아니라 `예상 범위`, `가능성`, `확정 여부` 정도로 제한하고, 계산 불가능한 상황은 명시적으로 `UNKNOWN`으로 표시해야 한다.

# 이건 짓지 마라

- `name`, `cost`, `effect`를 표시하지 않은 채 VFX만 더 화려하게 만들기.
- 카드 사용 전에 미리보기 없이 즉시 실행하는 숫자키 구조를 그대로 유지하기.
- 피해량을 정확한 단일 숫자로 예고해 난수·방어·크리티컬의 긴장을 제거하기.
- 색상만으로 역할·상태·위험을 구분하기.
- 상태 글리프를 추가하면서도 범례를 제공하지 않기.
- 현재 없는 적 intent 데이터를 임의로 만들어 화면에 넣기.
- 2초 시간 게이트를 카드별 적 공격 의도처럼 보이게 만들기.
- 모든 이벤트마다 화면 흔들림과 중앙 배너를 사용하기.
- ASCII 화면에 카드 장식, 긴 설명, 아이콘을 무리하게 추가하기.
- 상태 만료·루트·크레딧·페이즈 전환을 각각 완전히 다른 애니메이션 체계로 만들기.
- 연출 재생 중 입력을 막아 전투가 느려지게 만들기.
- 40×60에서 잘리는 80열 전용 UI를 먼저 구현하기.
- 실제 밸런스 수치를 바꾸는 방식으로 UI 문제를 해결하기.
