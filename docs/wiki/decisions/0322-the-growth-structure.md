# ADR-0322: 성장 구조 — 측정, 죽은 축 배선, 보이는 성장

**상태**: Accepted (오너 위임: *"지금까지 내용을 종합해서 반영해줘. 위임할게."*)
**날짜**: 2026-11-18
**결정자**: AI 위임
**우선순위**: P0 (성장 · 진행)

## 컨텍스트 (Context)

ADR-0319(회복 자동) · ADR-0320(실피해 공개) · ADR-0321(SRW 케이스) 이후, 오너가 **성장 구조 자체**를 물었고 측정이 예상 밖의 답을 냈다.

**성장은 4층에 걸쳐 있다** — 교전(없음) → 미션(덱·크레딧) → 계약(덱·크레딧·고유 이월 + advance) → 메타(prep 지갑·Far Grid·업적). 그리고 축은 넷: **덱 · 몸 · 고유 · 지갑**.

그런데 **이기는 플레이에서 덱은 자라지 않는다** (미션 종료 덱 장수, 시작 5장, 24시드/미션):

| 등급 | 항상 카드 | 아플 때 수리(스마트) |
| --- | --- | --- |
| g3 | 6.18장 (58.0%) | **5.03장** (84.1%) |
| g4 | 6.38장 (54.2%) | **5.02장** (85.4%) |
| g5 | **9.00장** (3.7%) | 5.99장 (28.7%) |
| g6 | 7.75장 (4.2%) | 5.74장 (47.2%) |

카드를 먹으면 덱은 자라지만 **죽는다**. 이기는 플레이는 전리품 정지를 **거의 매번 생존(수리)에 쓴다**. 즉 **수리 슬롯이 성장을 먹고 있다.**

**floor 스윕이 임계값을 찾았다** (스마트 정책):

| 회복 floor | g3 덱 / 승률 | g4 덱 / 승률 | g5 덱 / 승률 | g6 덱 / 승률 |
| --- | --- | --- | --- | --- |
| 50% (현행) | 5.03 / 84.1% | 5.02 / 85.4% | 5.99 / 28.7% | 5.74 / 47.2% |
| 65% | 5.03 / 92.0% | 5.02 / 99.2% | 6.05 / 29.6% | 5.78 / 56.9% |
| 80% | 5.08 / 98.5% | 5.05 / 100% | 6.60 / 38.9% | 5.90 / 62.5% |
| **90%** | **7.18** / 98.9% | **7.50** / 100% | 10.11 / 24.5% | 9.00 / 61.1% |

**덱이 자라기 시작하는 값은 90%** 이고, 그 대가로 g4 가 100% 가 된다. 즉 **성장과 난이도가 같은 손잡이에 묶여 있다** — 수리는 HP 가 85% 미만이면 항상 카드보다 값어치가 크므로, 수리가 쓸모없어질 만큼 회복을 올려야 카드가 선택된다.

## 결정 (Decision)

**죽은 축을 살리고, 성장을 보이게 한다. 난이도 손잡이는 측정된 채로 오너에게 넘긴다.**

### ⑴ EQUIPMENT 를 런에 배선한다 (결함 수정 · 밸런스 무영향)

전투는 `state.equipmentLoadout.totalStats()` 를 읽는데, `state.equipmentLoadout` 는 **항상 `EMPTY_LOADOUT`** 이었다(`makeInitialState` 가 만들고 아무도 채우지 않음). 메뉴는 **별개 객체** `this.equipmentLoadout` 을 고쳤고, 런 시작 때 그걸 **빈 값으로 덮어썼다** — 게다가 localStorage 에도 안 남아 새로고침에 사라졌다.

수정: `equipment_store.ts` 가 슬롯→장비 id 를 영속화하고(`prep_wallet` 과 같은 관용구), 부팅 시 복원하며, **잭인할 때 그 loadout 을 `state` 에 얹는다.**

**밸런스 무영향인 이유**: 메뉴가 장착할 수 있는 것은 tier-0 기본 장비뿐이고, 그 스탯(`programPower`·`apBonus`)은 **어떤 전투 경로도 읽지 않는다**(전투가 읽는 것은 `attackBonus`·`critBonusPct`·`damageBonusPct`). 측정으로 확인: `npm run balance` **byte-identical**(97.1/70.6/47.0). 즉 이 수정은 **축을 되살리지만 오늘의 숫자는 바꾸지 않는다** — 장비 획득 경로가 생기면 그때 밸런스 문제가 된다.

### ⑵ 성장을 한 줄로 보이게 한다

HUD 에 **`Deck {n} · T{평균 tier}[ · UNQ {k}]`** 를 추가한다. HUD 는 이미 크레딧과 장착 슬롯을 말했지만 **덱의 모양**은 아무 데도 없었다. 위 측정이 보여주듯 이 줄은 "성장이 일어나고 있는가"를 가장 빨리 읽는 방법이다.

### ⑶ 난이도 손잡이는 넘긴다 (측정치와 함께)

수리를 **영구 성장(`+최대 HP`)** 으로 바꾸거나 회복 floor 를 올리는 것은 **성장을 일으키는 대신 난이도를 크게 낮춘다**(위 표). 두 수치 모두 오너 영역이므로 **값을 바꾸지 않고 측정만 기록**한다. 다음 슬라이스의 입력이다.

## 결과 (Consequences)

- **성장 축**: 덱(측정상 거의 안 큼) · **몸(진짜 — advance `[0,0,20,70,185,140]`)** · **고유(계약당 1장)** · **지갑(승리 크레딧 50% 저금)** · **장비(이제 실제로 전투에 닿음, 현재 기본값은 무영향)**.
- **미해결**: 덱 성장이 성공 경로가 아니다(수리가 이긴다). floor/수리 재설계는 **오너 값 대기**.
- **크래프팅 고리**는 여전히 미확인(런에서 번 재료가 다음 런 제작으로 이어지는지).
