# 캠페인 + 메뉴 구조 재설계 (2026-11-15)

> ADR-0315 의 설계 문서. **결정 완료 + 슬라이스 1(메뉴) 구현 완료.**
>
> **2026-11-17 갱신**: ADR-0317 4단계가 `GRAPHIC NOVEL` 메뉴 항목을 삭제했다(스토리는 런의
> 프롤로그 한 곳). 메뉴는 **14 → 13항목**, 첫 런 직후는 **7 → 6항목**이다. 아래 Q8 행과 목록은
> 결정 당시의 기록이며, 현행은 코드(`renderer/menu_main.ts`)와 ADR-0315 구현 상태를 본다.

## 0. 결정 (2026-11-15)

**원칙(오너)**: "나열과 무엇인지 감도 못 잡는 것을 선택해야 하는 상황을 없애거나 줄인다."

**슬라이스 1 구현 결과**: 메뉴가 4그룹(PLAY · WORKSHOP · ARCHIVE · SYSTEM) + 항목별 설명으로
바뀌었고, **40열에서 0건 잘림**. 그 과정에서 ADR-0300 폭 가드가 **패널 클리핑을 감시하지 않던
구멍**을 발견해 봉합(`recordClippedText`)하고 메뉴를 가드 케이스에 추가했다.

아래 §1–§7 은 결정의 근거와 남은 슬라이스다.

## 0-b. 서사의 종착점 — 그래픽 노블은 사라진다 (ADR-0317)

오너 방침: **그래픽 노블 메뉴는 검증용 발판**이다. 완성 시점에는 **스토리에 모두 녹여내고
메뉴에서 없앤다.** 프롤로그와 이벤트에도 반영한다.

| 표면 | 무엇을 담나 | 출처 | 지금 |
|---|---|---|---|
| 미션 브리핑 | 이 미션이 무엇인지 한 줄 | `plot_summary` | ✅ ADR-0316 |
| **프롤로그** | 이 런의 자키가 누구인지 (런 시작) | GN 씬 + `prologue.md` | 🟡 메뉴 모드 |
| **이벤트** | 런 중 결정적 순간의 대사 | `event_dialogues.json`(v0.2, **미배선**) | ❌ |
| 엔딩 | 런이 어떻게 끝났는지 | `ending_resolver` | ✅ |
| ~~그래픽 노블 메뉴~~ | — | — | **제거 예정** |

**이관 순서**: ① 브리핑 ✅ → ② **프롤로그를 런에 결합 ✅**(NEW RUN → 자키 → 그 자키의 프롤로그 → 미션 목록, ESC는 이야기만 건너뜀) → ③ 이벤트 배선 → ④ 메뉴 항목 제거.
그때까지 **그래픽 노블 화면에 새 기능을 넣지 않는다**(씬은 이관 자산).

## 1. 현재 구조 (실측)

**메뉴 — 평면 14항목** (`renderer/menu_main.ts`, 2026-11-15 당시; 지금은 13항목):

```
NEW RUN · FAR GRID · DUNGEON CRAWL · GRAPHIC NOVEL · CONTINUE · SETTINGS ·
CRAFT · EQUIPMENT · CREDITS · HALL OF DEAD · HELP · ENDINGS · STATS · TUTORIAL
```

플레이 모드(6) · 시스템(4) · 설정/기록(4)이 **한 열에 섞여** 있다.

**진행**: `NEW RUN → jockey_select → mission_select(53 평면) → prep → 런(미션 1개) → 엔딩 → 타이틀`.
`FAR GRID` 는 별도 유니버스(Arc 1 클리어로 개방)에 자체 허브.

**콘텐츠 분포** (`missions.json`):

| | 값 |
|---|---|
| 미션 | 53 (sprawl **33** · far-grid 20) |
| arc | 1:**20** · 2:14 · 3:8 · 4:7 · 5:4 |
| 등급 | g1 4 · g2 16 · g3 11 · g4 10 · g5 9 · g6 3 |
| 자키 | 3 (novice · veteran · heretic) |
| 엔딩 | 32 (arc별 7/7/6/6/6) |

**죽은 것**: `missionsCompleted` 가 **항상 1** 이라 `liberation` 엔딩(>=3)은 도달 불가
(ADR-0270/0271 이 문서화). `requiresFaction`/`requiresChoice` 는 선언 0개.

## 2. 측정된 제약 — 덱을 이월하면?

캠페인의 핵심 가정은 "덱이 자라서 다음 미션으로 간다"이다. 하네스에 이월 덱을 넣어
**같은 미션·같은 시드로 신규 vs 이월**을 비교했다(32시드, 최적 정책):

| 등급 | 신규 | 이월 | 차이 | 이월된 덱 크기 |
|---|---:|---:|---:|---:|
| 1 | 100.0% | 100.0% | +0.0pp | 5.9 |
| 2 | 96.5% | 97.3% | +0.8pp | 5.3 |
| 3 | 74.4% | 75.0% | +0.6pp | 5.0 |
| 4 | 50.6% | 48.8% | −1.9pp | 5.0 |
| 5 | 29.9% | 28.5% | −1.4pp | 5.9 |
| 6 | 31.3% | **63.5%** | **+32.3pp** | 5.7 |

**두 가지 발견:**

1. **덱은 자라지 않는다.** 이월된 덱이 **5.0~5.9장** — 최적 플레이가 전리품 칸을 **수리**에
   쓰기 때문이다(ADR-0305/0306). 즉 캠페인의 성장은 **덱이 아니라** HP·크레딧·고유에서 온다.
2. **g6 에서만 곡선이 깨진다**(+32.3pp). 이유는 **고유 카드**(ADR-0303/0311) — g6 는 장갑
   관통이 승패를 가르는데, 이월되면 그 답이 **상시**가 된다.

→ **캠페인은 g1–g5 에서는 안전하고, g6 에서만 별도 규칙이 필요하다.**

## 3. 제안 A — 메뉴 (Jev: "그룹화" 질량 0.97, 모양은 미결정)

**A안 (Jev 최빈값, 0.43)** — 3그룹:

```
        ┌ PLAY ────────────┐   ┌ ARCHIVE ─────────┐   ┌ SETTINGS ────────┐
        │ CAMPAIGN  (기본) │   │ HALL OF DEAD     │   │ SETTINGS         │
        │ QUICK RUN        │   │ ENDINGS          │   │ HELP             │
        │ FAR GRID         │   │ STATS            │   │ CREDITS          │
        │ DUNGEON CRAWL    │   └──────────────────┘   └──────────────────┘
        │ GRAPHIC NOVEL    │
        │ TUTORIAL         │        CONTINUE 는 세이브가 있으면 최상단
        └──────────────────┘        (CRAFT/EQUIPMENT 는 PLAY 안의 WORKSHOP)
```

**B안 (0.31)** — 모드 우선: 최상단이 플레이 모드(CAMPAIGN/QUICK/FAR GRID/DUNGEON/GN),
메타는 하위 서브메뉴.

**C안 (0.23)** — 5그룹: PLAY · RECORDS · WORKSHOP · OPTIONS · CONTINUE.

세 안 모두 **CONTINUE 를 최상단**에 두고 **CRAFT/EQUIPMENT 를 플레이 옆 WORKSHOP** 으로 묶는다.

## 4. 제안 B — 런 = 캠페인 (Jev: 기본값 0.76, conf 0.64)

```
NEW RUN → jockey_select → CONTRACT(arc 선택) → 미션 1 → [결과] → 미션 2 → … → 엔딩 → 타이틀
```

- **캠페인이 기본**, `QUICK RUN`(단일 미션)은 남긴다.
- **계약(contract)** = 한 arc. 그 arc 의 미션을 순서대로/선택으로 소화한다.
- 각 미션 뒤 **전리품 화면이 곧 "다음 계약" 선택**이 된다(현재의 mission_select 를 재사용).
- `missionsCompleted` 가 **실제 카운트**가 되고 `liberation` 엔딩(>=3)이 살아난다.
- **죽으면 캠페인 종료**(현행과 동일) — 런 = 캠페인.

### 무엇이 이월되는가 (측정 기반)

| 자원 | 이월 | 근거 |
|---|---|---|
| **덱** | ✅ | 측정상 거의 중립(g1–g5). g6 만 규칙 필요 |
| **HP** | ❓ 결정 | 이월하면 g1–g5 가 쉬워진다 — 미션 사이 회복 규칙이 필요 |
| **크레딧** | ✅ | ADR-0314 로 엔딩 조건이 됐다 — 이월해야 의미가 누적된다 |
| **COST(alarm)** | ❌ | 미션 단위 예산(ADR-0294) |
| **고유** | ⚠️ | **캠페인당 1장**이어야 한다(현행 "런당 1장" = 캠페인당 1장) |

## 5. 리스크

1. **g6 고유 누적** — 캠페인 후반 g6 는 이월된 고유 때문에 +32.3pp. 목표를 캠페인 기준으로
   다시 잡거나, 고유를 "이 런(캠페인)에 1장"으로 유지하고 g6 목표를 조정해야 한다.
2. **저장 스키마** — 캠페인 상태(미션 인덱스·계약·이월 자원)가 슬롯에 필요하다. `version 1`
   유지가 목표(선택 필드 관례, ADR-0287/0311).
3. **밸런스 기준선** — 현행 목표는 **미션 단위**다. 캠페인은 "3미션 생존율" 같은 **새 지표**가
   필요하다(현재 하네스에 없음).
4. **mission_select 의 정체성** — 지금은 "53개 중 아무거나"다. 캠페인에서는 **계약 보드**가
   된다. QUICK RUN 은 현행 목록을 유지.
