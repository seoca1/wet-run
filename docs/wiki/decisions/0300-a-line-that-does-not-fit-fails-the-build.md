# ADR-0300: 넘치는 줄은 빌드를 실패시킨다 — 잘린 글자를 조용히 잃지 않는다

**상태**: Accepted
**날짜**: 2026-11-08
**결정자**: 오너 ("Continue." — ADR-0299 (c))
**우선순위**: P1 (UI 회귀 방지)
**관련**: [ADR-0299 — 전리품 화면은 40열에서 잘렸다](./0299-the-loot-screen-did-not-fit.md) · [ADR-0297 — 조합은 이미 있었다](./0297-the-combination-already-existed.md) · [ADR-0251 — 화면은 사실을 말한다](./0251-the-screen-states-what-happens.md)

> 이 세션에서 **같은 실수를 두 번** 했다: 화면이 약속하지 않아야 할 것을 약속했고(거짓 어포던스),
> 화면이 **말해야 할 값을 잘라먹었다**(`+75 HP → 2`). 둘 다 **테스트가 없어서** 늦게 발견됐다.
> 두 번째는 **구조적으로** 막을 수 있다: 글자를 그리는 그 자리에서 잰다.

## 결정 (Decision)

`setText` 가 **오른쪽 경계를 넘는 텍스트를 기록**한다.

```ts
export function takeClippedText(): readonly string[]; // 꺼내고 비운다
```

- 기록은 **최대 64개**(비정상 프레임이 메모리를 먹지 않도록).
- 테스트는 **화면 × 레이아웃(40·60·80)** 을 렌더하고 **목록이 비어 있는지** 단언한다.
- 실패하면 **잘린 문자열이 그대로 출력**되므로 무엇이 안 들어갔는지 즉시 보인다.

## 측정 (Measurement)

도구가 **스스로 동작하는지** 먼저 증명한다(아무것도 기록하지 않는 가드는 가드가 아니다):

| 케이스 | 결과 |
|---|---|
| 10열 그리드에 `"0123456789ABCDEF"` | `["0123456789ABCDEF"]` 기록 |
| 20열 그리드에 `"fits fine"` | `[]` |
| 두 번째 읽기 | `[]` (드레인됨) |

그리고 현재 화면들:

| 상태 | 40×60 | 60×40 | 80×50 |
|---|---|---|---|
| 전리품 (흔적 80, 카드 3 + 5옵션) | 0 | 0 | 0 |
| 전리품 (흔적 0) | 0 | 0 | 0 |
| 매트릭스 | 0 | 0 | 0 |
| 엔딩 | 0 | 0 | 0 |

**전부 0** — ADR-0299 의 수정 이후 넘치는 줄이 없다.

## 결과 (Consequences)

- **회귀가 자동으로 잡힌다**: 옵션을 하나 더 붙였는데 40열에서 안 들어가면 **테스트가 실패**하고
  **그 문자열**을 보여준다.
- **거짓 어포던스 계열의 두 번째 축**(잘린 약속)이 막혔다. 첫 번째 축(HUD 가 동작하지 않는 키를
  부르는 것)은 ADR-0297 이 문구를 실제 제공 옵션에서 조립해 막았다.
- **생산 비용 없음**: 넘치는 줄이 없으면 `setText` 에 추가되는 것은 **비교 한 번**이다.
- **불변**: 게임 규칙·곡선·저장 형식·렌더 결과(기록만 추가).

## 열린 질문

- **(a) 나머지 화면으로 확대.** prep·mission select·codex·crafting 도 훑어야 한다. 각 화면의 뷰
  타입을 실제로 만들어야 하므로 화면별 작업이다.
- **(b) 경고 vs 실패.** 지금은 테스트에서만 실패한다. 개발 중에는 `console.warn` 을 붙여 **즉시**
  보이게 할 수 있다(소음이 늘어남).
- **(c) 세로 넘침.** 지금 가드는 **가로**만 본다. 줄이 화면 밖으로 나가는 경우(행 초과)도 같은
  방식으로 잡을 수 있다 — 전리품이 9칸이 되면 이쪽이 먼저 터진다(ADR-0299 (a)).
