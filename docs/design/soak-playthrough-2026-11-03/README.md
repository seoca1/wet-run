# 직접 컨트롤 진행 테스트 — 계획과 소크 하네스 (2026-11-03)

## 왜 이게 필요한가

지금까지 발견된 두 결함은 **둘 다 손으로, 하나씩** 찾았다:

| 발견 | 경로 | 고친 곳 |
|---|---|---|
| 죽음 화면에서 못 나옴 | 오너 플레이 → FLATLINE | ADR-0263 |
| **전투 중 정지** | 오너 플레이 → COST 상한 | **미수정 (이 문서)** |

손으로 하나씩 찾는 방식은 **발견 편향**이 있다: 우연히 밟은 것만 찾고, 얼마나 자주 나는지는 모른다.
"한 번 봤다"는 비율이 아니다. 그래서 **실제 빌드를 실제 키로 여러 번 플레이하는 하네스**를 만들고,
정지를 **분류**하고, **비율과 신뢰구간**으로 보고한다.

## 이번에 확정한 결함 — 전투 정지 (COST 상한)

코드 + 실측으로 확정:

```
useProgram:  alarm + cost > 100  →  거절("Cost too high — program failed")
applyCombatAction(use_program):  손패 길이가 그대로면 → 조기 반환
                                 (적 턴 없음 · 손패 리필 없음)
GameAction:  "턴 넘기기" 가 없다
tickAlarm:   alarmLevel(TRACE) 만 올린다 — COST(player.alarm) 는 줄지 않는다
```

**실측(독립 headless, 실제 전투 → COST 를 상한으로)**:

```
blocked: true (손패 5장 전부 상한 초과)
  Enter · Space · 숫자 · 방향키   →  전부 변화 없음
  20초 무입력                    →  적이 때리지 않음, COST 그대로 (자동 진행 없음)
  ESC                          →  "Jacked out — mission failed"  ← 유일한 출구 = 런 실패
```

즉 **전투 턴은 "손패를 다 쓰면" 진행되는데, 상한에 닿으면 아무 카드도 못 써서 턴이 영원히 진행되지 않는다.**
플레이어가 할 수 있는 일은 `ESC`(런 포기)뿐이다. 이것이 오너가 "전투 중에 멈췄다"고 한 상태다.

## 계획

### 1) 하네스: `web/e2e/soak_playthrough.spec.ts` (`npm run soak`)

| 원칙 | 내용 |
|---|---|
| **실제 키만** | `wetrun.state` 를 절대 쓰지 않는다. 리듀서·컨트롤러는 플레이어가 다루는 그대로다 |
| **정책이 몰고, 스윕은 진단만** | 전체 키 스윕은 **정책 행동이 아무것도 못 바꿨을 때만** 돈다 (건강한 런을 마구 흔들지 않는다) |
| **"정책이 헤맸다" ≠ "게임이 멈췄다"** | 진행 키(Enter/Space/Tab/1-9/방향키/문자)를 **두 번** 스윕해도 아무것도 안 바뀔 때만 정지로 인정 |
| **포기 키 분리** | `Escape` 와 `q` 는 둘 다 `jack_out` 이다. 진행 스윕에서 빼고, "포기만 가능"을 **별도 분류**로 둔다 |
| **결정적** | 런은 미션에서 시드된다. 정책은 관측 상태의 순수 함수(시드된 `random` 제외) → 같은 (미션, 정책)은 같은 결과 |
| **전수조사** | 결정적이므로 같은 셀을 반복해도 새 정보가 없다. 그래서 **미션 전체 × 정책**을 돈다 |

**분류**

| 결과 | 의미 |
|---|---|
| `completed` / `failed` | 엔딩 도달 / 사망 |
| `deadlocked` | 어떤 키도 상태를 바꾸지 않는다 |
| `only_escape_loses` | 진행 키가 전부 무력하고, `Escape`/`q` 만 반응하는데 그건 **런 상실** |
| `no_end_in_steps` | 상태는 계속 변하지만 끝에 도달하지 못함 (별개 발견) |

**기록**: 미션·등급·정책·결과·스텝, 정지 시 `phase`/`turn`/`COST`/손패/쓸 수 있는 카드 수/ICE HP/포기 키 결과.
추가로 런별 `maxAlarm`(COST 최고치)과 `minAffordable`(전투 중 쓸 수 있는 카드 최소 수).

**집계**: 결과 분포, 정책별, 등급별, 정지 phase 별, Wilson 95% 구간, COST 상한 도달률.

### 2) 표본

- **미션 53 × 정책 3(cheap/expensive/random) = 159 런** (전수조사, 반복 없음).
- 런당 상한 `SOAK_MAX_STEPS=320`, 진행 정지 가드 `SOAK_STALL=35`.

### 3) 수용 기준 (이 계획이 "충분히 했다"고 말할 수 있는 조건)

1. 하네스가 **정상 런을 정지로 오판하지 않는다** — 알려진 정상 런(엔딩/사망 도달)은 전부 `completed`/`failed`.
2. 알려진 결함(COST 상한 정지)을 **하네스가 스스로 찾아낸다** — 미션이 아니라 상태에서.
3. 비율을 **점이 아니라 구간**으로 보고한다.
4. 모든 정지가 **재현 가능**하다 — 같은 (미션, 정책, 시드)로 다시 돌리면 같은 상태에서 멈춘다.

### 4) 수정 (별도 ADR, 오너 결정)

정지는 **리듀서 규칙**이라 밸런스에 닿는다. 후보:

| | 안 | 내용 | 밸런스 |
|---|---|---|---|
| **D1** | **턴 패스** | 쓸 수 있는 카드가 없으면 `ENTER` = 턴 넘기기 → 적 턴 진행 | 접촉 (적이 더 때림) |
| **D2** | **자동 턴 진행** | 상한에서 손패가 전부 막히면 턴을 자동 종료 | 접촉 |
| **D3** | **상한 도달 시 ESC 안내** | `COST capped — ESC: JACK OUT (run fails)` 한 줄 | 무변경 |
| **D4** | **COST 를 턴마다 감소** | 압박을 유지하면서 막힘을 푼다 | 접촉 (큰 변경) |

D1/D2 는 "막히면 그냥 진다"를 "막히면 맞으면서 턴이 간다"로 바꾼다 — 정지를 없애고 압박은 남긴다.
D3 은 정지를 남기지만 플레이어가 상황을 알게 한다(ADR-0251 §5). **D1+D3 조합을 추천.**

## 결과 — 전수조사 159 셀 (미션 53 × 정책 3, 반복 없음)

| 항목 | 값 |
|---|---|
| 완주 / 정지 | **143 / 16** (`no_end_in_steps` 0, `deadlocked` 0) |
| **정지율** | **10.06%**, Wilson 95% **6.29 – 15.72%** |
| 정책별 정지 | `cheap` **0/53** · `expensive` **0/53** · `random` **16/53 (30.2%)** |
| 정지 위치 | **16/16 `combat/combat`** |
| 정지 시 COST | **98 – 100** (상한 100) |
| 정지 시 쓸 수 있는 카드 | **0장 (16/16)** |
| 포기 키 결과 | `dead/defeat` — **런 상실** |
| 정지 등급 분포 | g5 9 · g4 4 · g6 2 · g3 1 → **긴 전투**에 몰림 |
| 평균 | 28.2 스텝 / 8.3 초 |

**읽는 법**: 이건 표본이 아니라 **전수조사**다(게임이 결정적이라 같은 셀 반복은 정보가 없다).
그래서 "10.06%"는 *이 세 정책으로 이 53개 미션을 플레이했을 때* 의 정확한 비율이고,
Wilson 구간은 미션 목록을 모집단으로 봤을 때의 불확실성이다.

**핵심**: 정지는 **비효율적으로 오래 싸운 `random` 정책에서만** 나온다(30.2%). 상한은 "카드를 많이 써야" 닿으므로,
합리적으로 싸우면(`cheap`/`expensive`) 106런 전부 정지하지 않았다. 즉 이 결함은
**"오래 끌면 게임이 서고, 포기해야 한다"** 이며, 초보자·느린 플레이에 불리하다.

| 기준 | 결과 |
|---|---|
| 정상 런을 정지로 오판하지 않는다 | ✅ 143 완주 / 오탐 0 |

## 하네스 개발 중 잡은 자체 버그 5개 (모두 도구 쪽)

1. 키 목록을 미리 만들어 나중에 누르면 **자기 효과를 못 본다** → 누르고 읽는 구조로
2. 진행 스윕에 **`q`(=`jack_out`)** 가 섞여 **정상 런을 스스로 포기시켰다**
3. **BYPASS 한 노드**를 미해결로 봐서 같은 노드로 무한 회귀
4. **거절 메시지가 번갈아 바뀐다** — 상한에서 `1`="Cost too high", 빈 슬롯 `6`="Hand slot 6 is empty"
   → 스윕이 매번 "변화 있음"으로 읽어 **정지를 한 번도 분류하지 못했다**. 메시지를 분리해 해결
5. **idle alarm 이 스스로 `TRACE n/5` 를 쓴다** — 키 없이 텍스트가 바뀌어 정지를 가림 (4의 수정이 함께 해결)

1~3을 고치기 전의 수치는 무효다. 4 때문에 **첫 조사는 수치는 맞았지만 분류가 틀렸다**(16건을 `no_end_in_steps` 로).
