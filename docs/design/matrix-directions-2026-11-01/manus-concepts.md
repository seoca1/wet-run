## 안 1 — 데이터 요새의 평면도

**한 줄 은유:** “침입할수록 내부가 드러나는 데이터 요새의 평면도.”

### 플레이어가 매 순간 하는 일

- `WASD` 또는 방향키로 현재 노드에서 다음 노드 후보를 커서로 고른다.
- `ENTER`로 노드에 접근한다.
- 미클리어 ICE를 만나면 즉시 화면이 `ICE GATE` 상태로 전환된다.
- `P`로 PROBE, `B`로 BREACH, `V`로 BYPASS, `J`로 JACK OUT.
- 유틸리티 프로그램을 가지고 있다면 `S`로 프로그램을 폐기해 SCAN한다.
- 한 번에 전체 지도를 읽는 것이 아니라, 현재 위치 주변의 방과 통로가 점진적으로 밝혀진다.

### 무엇이 게임처럼 느껴지는가

노드가 표의 행이 아니라 요새 내부의 **방과 문**으로 보인다. 플레이어는 “다음 목록 항목”을 고르는 것이 아니라, 여러 개의 문 중 하나를 열고 들어간다.

- 지나온 노드는 열린 방으로 남는다.
- 방문하지 않은 노드는 `???` 또는 잠긴 문으로 표시된다.
- ICE가 있는 통로는 두꺼운 차단선으로 보인다.
- 새 노드에 진입할 때마다 주변 방이 한 번에 드러나는 짧은 입력 기반 애니메이션을 넣을 수 있다.
- BREACH 성공 시 차단선이 깨지고, 실패 시 플레이어 아이콘 주변에 균열 문자가 생긴다.

### 위험·목표·깊이가 읽히는 방식

- **목표:** 중앙 또는 가장 깊은 곳의 `EXIT / BOSS` 방.
- **위험:** ICE가 있는 방은 `###`, 봉쇄 통로는 `|||`, 미확인 방은 `?`.
- **깊이:** 화면의 아래쪽이나 안쪽으로 들어갈수록 `SURFACE > MID > CORE` 레이어가 겹친다.
- **보상:** 방 안의 데이터 캐시, 크레딧, 도구 아이콘으로 표시한다.
- **끝:** `EXIT` 방을 통과하면 지도가 더 이상 확장되지 않고 런이 종료된다.

### 가장 큰 실패 위험

실제 지형이 아니라 **던전 모양으로 꾸민 노드 목록**에 그칠 수 있다. 통로별로 서로 다른 위험과 정보가 없다면 평면도의 의미가 약해진다.

- 현재 위치에서 직접 연결된 세 노드만 표시한다.
- `FEED` 문구와 긴 내레이션은 제거한다.
- `ICE GATE`는 지도 아래가 아니라 별도 화면으로 전환한다.

## 안 2 — 하강하는 트레이스

**한 줄 은유:** “콘솔 카우보이가 데이터 심연으로 내려가는 단방향 트레이스.”

### 플레이어가 매 순간 하는 일

- 화면 아래의 현재 위치에서 시작해 위쪽의 깊은 층으로 올라간다.
- 각 층마다 좌우로 갈라지는 2~3개의 트레이스 중 하나를 선택한다.
- `A/D`로 트레이스를 바꾸고 `ENTER`로 내려간다.
- ICE를 만난 순간 트레이스가 멈추고, 그 선 위에서 통과 방식을 선택한다.
- `P`, `B`, `V`, `S`, `J`는 현재 트레이스 위의 ICE에 직접 적용된다.

이 방향은 이동 선택을 매우 단순하게 만들어, 플레이어가 “지도 조작”보다 **위험한 하강 결정을 빠르게 반복**하도록 한다.

### 무엇이 게임처럼 느껴지는가

화면 전체가 아래에서 위로 뻗는 하나의 경로가 된다. 플레이어는 “다음 행”을 읽는 것이 아니라, 매번 **어느 선을 탈지** 결정한다.

- 현재 트레이스는 점선이나 `=`로 깜빡인다.
- 선택하지 않은 트레이스는 어두운 회색이 아니라 끊긴 선과 작은 신호로 남는다.
- 이전 선택은 뒤에 흔적으로 남아 되돌아갈 수 없다는 사실을 강조한다.
- 입력할 때마다 한 층이 위로 밀려나는 프레임 갱신이 가능하다.
- 깊어질수록 트레이스 간격이 좁아지고 ICE가 선을 가로막는다.

### 위험·목표·깊이가 읽히는 방식

- **목표:** 화면 최상단의 `CORE EXIT`.
- **위험:** 선을 가로막는 `ICE`, 깨진 선, 경고 신호.
- **깊이:** 현재 하강 횟수와 층 이름으로 읽는다.
- **보상:** 각 층의 옆가지에 캐시, 도구, 휴식 노드가 붙는다.
- **선택의 의미:** 짧은 길은 ICE가 많고, 우회 길은 길지만 자원 회복이 가능하다.

### 가장 큰 실패 위험

경로가 일직선으로만 보이면 **선택의 긴장감이 사라지고 타이밍 없는 메뉴 이동**처럼 느껴질 수 있다. 갈림길마다 보상·위험의 성격이 확실히 달라야 한다.

### 80×50 ASCII 목업

- 위아래 층을 모두 보여주지 않고 현재 층, 다음 층, 목표만 표시한다.
- 이전 경로는 하나의 `TRACE` 선으로 압축한다.
- 캐시 보상 수치 대신 `CACHE`, `TOOL`, `REST`만 표시한다.
- `FEED`는 제거하거나 하단 한 줄로 줄인다.
- 현재 선택 후보와 ICE 조우 화면을 번갈아 보여준다.

## 안 3 — 해킹 콘솔 보드

**한 줄 은유:** “노드를 고르는 것이 아니라, 손상된 시스템 보드에 점퍼를 꽂아 신호를 연결한다.”

### 플레이어가 매 순간 하는 일

- 화면에 여러 노드와 포트가 표시된다.
- 커서로 `WASD`를 이동해 연결 가능한 노드를 선택한다.
- `ENTER`로 현재 포트와 다음 노드를 연결한다.
- 연결할 때마다 신호가 한 칸씩 전진한다.
- ICE 포트에 도달하면 보드가 `SECURITY HANDSHAKE` 모드로 바뀐다.
- `P`, `B`, `V`, `S`, `J`로 통과 방식을 결정한다.
- 잘못된 연결을 선택하면 신호가 되돌아가거나, 경보 카운트가 오른다.

### 무엇이 게임처럼 느껴지는가

노드가 고정된 목록이 아니라 **전류가 흐르는 회로의 접점**으로 작동한다.

- 현재 위치는 `@`가 아니라 흐르는 신호 `>>>`로 표현한다.
- 선택한 경로에 전류가 들어오면 선이 채워진다.
- ICE는 단순한 노드가 아니라 회로를 끊는 퓨즈처럼 보인다.
- BREACH는 ICE의 포트를 정면으로 연결하는 행동이다.
- BYPASS는 우회 점퍼를 태워 회로를 건너뛰는 행동이다.
- SCAN은 유틸리티를 회로에 소모해 주변의 숨은 포트를 밝히는 행동이다.

### 위험·목표·깊이가 읽히는 방식

- **목표:** 보드 오른쪽의 `EXIT BUS`.
- **위험:** 열린 회로, 붉은 경고선 대신 `!!!`, ICE 퓨즈, 끊긴 접지선.
- **깊이:** `BUS 1 / BUS 2 / CORE BUS`로 구획한다.
- **보상:** 회로의 분기 끝에 도구 모양의 프로그램 슬롯이 있다.
- **죽음:** 경보 게이지가 차거나 전투에서 패배하면 회로가 끊기며 런이 종료된다.

### 가장 큰 실패 위험

회로 연결 규칙이 명확하지 않으면 플레이어가 **경로를 선택하는 것이 아니라 퍼즐 규칙을 해석하느라 멈추게** 된다. 분기 규칙은 실제 회로 퍼즐보다 시각적 선택 표시가 우선이어야 한다.

### 80×50 ASCII 목업

```text

 COST 184cr   UTILITIES [WORM] [EMPTY]         BYPASS 1 LEFT
-----------------------------------------------------------------------------
 INGRESS BUS                                               EXIT BUS
    |                                                        |
    |          +--------[ N04 CACHE ]--------+               |

    +----N02---+                            +----N07 BOSS----+

                                    \             |
                                     +----[ N08 ICE ]---+
                                     |      FUSE         |
                                     |      HP ???       |
```

### 40×60에서 버리는 것

- `INGRESS BUS`, `EXIT BUS` 라벨을 제거하고 시작점과 목표 포트만 남긴다.
- 회로 장식과 보조 포트를 제거한다.
- `ACTIVE TRACE`는 화면 중앙의 한 줄로 유지한다.
- 보드가 좁아지면 세로 배치로 바꾸고, 한 화면에 분기 3개만 보여준다.
- 경보 수치는 아이콘과 숫자 하나로 축약한다.

## 안 4 — 전기 회로도형 “전쟁 지도”

**한 줄 은유:** “플레이어와 ICE가 같은 회로 위에서 서로의 영역을 잠식하는 전기 전쟁.”

### 플레이어가 매 순간 하는 일

- 플레이어 신호 `@`가 회로망 위를 한 칸씩 이동한다.
- 연결된 노드 중 하나를 선택하면, 이동 전 미리 경로와 위험이 표시된다.
- `ENTER`로 이동을 확정한다.
- ICE 노드에 접근하면 ICE가 차단막을 펼치고, 플레이어는 통과 방식을 선택한다.
- `P`로 ICE의 실루엣을 밝혀 전투 수치와 보상을 확인한다.
- `S`로 유틸리티를 태워 인접 영역 전체를 스캔한다.
- `B`는 해당 노드를 점령하고 전투에 진입한다.
- `V`는 현재 회로를 강제로 건너뛰지만, 해당 노드의 보상 영역은 사라진다.

### 무엇이 게임처럼 느껴지는가

이 방향은 지도를 정적인 그래프로 두지 않고, **플레이어 영역과 ICE 영역이 움직이는 보드**로 만든다.

- 플레이어가 방문한 노드는 `+` 영역으로 잠긴다.
- ICE는 `#` 영역으로 인접 회로를 잠식한다.
- 입력할 때마다 ICE가 한 칸 확장되거나, 안전한 회로가 닫힌다.
- 단, 연속 게임 루프 없이 플레이어 입력 후에만 한 번 갱신된다.
- 지도 자체가 “지금 갈 수 있는 곳”뿐 아니라 “다음 입력으로 닫힐 수 있는 곳”을 보여준다.

### 위험·목표·깊이가 읽히는 방식

- **목표:** 회로의 바깥쪽이 아니라 내부의 `CORE / EXIT`.
- **위험:** ICE의 `#` 확장 방향과 차단될 것으로 예측되는 선.
- **깊이:** 회로의 동심원 레이어로 표현한다.
  - 바깥 고리: `SURFACE`
  - 중간 고리: `MID`
  - 중심: `CORE`
- **보상:** 플레이어가 점령한 노드 주변의 자원 토큰.
- **긴장:** 현재 갈 수 있는 경로가 많아 보여도 ICE 확장 때문에 다음 턴에는 하나가 사라질 수 있다.

### 가장 큰 실패 위험

플레이어 입력마다 지도가 바뀌면 **공정하지 않은 랜덤성**처럼 느껴질 수 있다. ICE의 다음 확장 방향과 차단 예정 경로를 항상 미리 표시해야 한다.

# 권장안: 안 1 — 데이터 요새의 평면도

가장 권하는 것은 **데이터 요새의 평면도**다.

이 게임의 핵심은 빠른 퍼즐보다 **한 번뿐인 침투에서 경로를 고르고, ICE를 어떻게 통과할지 감수하는 것**이다. 평면도는 이 핵심을 가장 직접적으로 표현한다.

- 노드 선택은 “목록에서 항목 고르기”가 아니라 “다음 방에 들어가기”가 된다.
- 미클리어 ICE는 지도 위의 실제 문과 봉쇄선으로 보인다.
- 보스는 단순히 `N07`이라는 행이 아니라, 요새 안쪽에 있는 목적지로 읽힌다.
- 지나온 경로가 화면에 남기 때문에 한 번의 런이 하나의 침투 기록이 된다.
- 좁은 화면에서도 현재 방과 다음 방만 남기면 구조를 유지할 수 있다.
- `PROBE / BYPASS / BREACH / SCAN / JACK OUT`은 별도 메뉴가 아니라 “잠긴 문 앞에서의 선택”이 된다.

안 2는 긴장감과 가독성이 가장 좋고, 안 3은 시스템적인 해킹 감각이 강하다. 안 4는 가장 역동적이지만, ICE의 입력 기반 확장 규칙을 공정하게 설명하는 비용이 크다.

권장 조합은 다음과 같다.

- 기본 공간: **안 1의 요새 평면도**
- 진행 표현: **안 2의 하강 트레이스**
- ICE 처리 화면: **안 3의 핸드셰이크 보드**

즉, 평상시에는 방과 통로를 탐색하고, 노드 진입 시에는 트레이스가 해당 방으로 이어지며, ICE 앞에서는 회로 보드형 결정을 내리는 구조다. 단, 세 화면이 서로 다른 게임처럼 보이지 않도록 `@`, 경로선, ICE 차단선 같은 공통 시각 언어를 유지해야 한다.

# 내가 놓친 5번째 방향: “침입 기록 테이프”

**한 줄 은유:** “현재 침투와 과거의 실패한 침투 기록이 겹쳐 보이는 블랙박스.”

이 방향에서는 일반적인 맵 대신, 현재 런의 움직임이 화면에 **기록된 경로 테이프**처럼 쌓인다.

```text
 MATRIX // BLACKBOX TRACE
 RUN 01 / LIVE                                DEAD RUNS STORED: 02
-----------------------------------------------------------------------------
 CORE EXIT
     |
     |              old run A
     |             . . . . . X
     |            /
     +------?----+------ICE------?
            |
            | current trace
            |
           @ YOU
            |
       N02---+---N04
        |          \
      REST        CACHE
-----------------------------------------------------------------------------
 OLD TRACE A: died at N08 / BREACH
 OLD TRACE B: BYPASS used / extracted with no reward
-----------------------------------------------------------------------------
 [W][A][S][D] choose route    [ENTER] enter node
 [P] PROBE  [B] BREACH  [V] BYPASS  [S] SCAN  [J] JACK OUT
```

과거 사망 런은 새로운 플레이어에게 직접적인 보너스가 아니라, **위험의 흔적과 정보의 유령**으로 남는다.

- 같은 ICE에서 누군가 죽었다는 `X` 표시가 보인다.
- 과거에 BYPASS를 쓴 경로는 보상이 비어 있는 선으로 남는다.
- 이전에 SCAN한 노드는 일부 정보만 영구적으로 남길 수 있다.
- 플레이어는 “이 길이 최단인가?”보다 “이 길에서 이미 누군가 죽었는가?”를 고민한다.

이 방향의 장점은 **Flatline의 무게**를 화면에 직접 남긴다는 점이다. 단점은 사망 기록이 영구 진행처럼 보이면 `죽으면 끝`이라는 원칙을 약화시킬 수 있다는 것이다. 따라서 과거 런은 능력이나 자원으로 변환되지 않고, 오직 불완전한 흔적과 분위기만 제공해야 한다.
