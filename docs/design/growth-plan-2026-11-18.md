# 성장 계획 — 2026-11-18

**목표(오너 지시)**: *"성장 요소를 제대로 계획해줘. 비주얼이나 선택지나 점점 좋아지는 모습이 보여야 흥미가 유지될 거야."*

즉 성장은 세 가지를 동시에 만족해야 한다:

1. **실재할 것** — 실제로 강해져야 한다(수치).
2. **보일 것** — 화면에서 "점점 좋아지는 모습"이 읽혀야 한다(비주얼).
3. **선택일 것** — 플레이어가 *무엇으로* 강해질지 고를 수 있어야 한다(선택지).

현재는 (1)이 부분적으로만 있고, (2)가 거의 없고, (3)은 회복이 성장과 경쟁해서 망가져 있었다(ADR-0319 가 절반을 고쳤다).

## 1. 현재 성장 축 (실측 · 코드 근거)

| 축 | 무엇이 자라나 | 언제 | 근거 |
| --- | --- | --- | --- |
| **덱** | 카드 3장 중 1장 | 매 전투 승리 | `state/card_reward.ts` — 게임에서 카드를 얻는 **유일한** 방법 |
| **몸** | 최대 HP·실드 | 런 시작 + **다리마다** advance | `state/prep.ts` · `main.ts` `contract_prep` |
| **지갑** | 크레딧(런) · prep 지갑(영속) | 킬 bounty + 미션 보상 / 승리 크레딧의 50% | `combat/victory.ts` · `state/prep_wallet.ts` |
| **고유** | 고유 프로그램 1장 | 계약당 1회(tier 6 승리) | `card_reward.ts` (ADR-0303/0311) |
| **메타** | Far Grid 해금 · 업적 · prep 지갑 | 런 완료 | `dungeon/far_grid_gate.ts` · `state/achievements.ts` |

**런 안에서 이월되는 것**(계약 3다리): 덱 · 크레딧 · 고유. **리셋**: HP(만피) · COST · 턴 · 보드. (`state/state.ts` `startNextLeg`)

## 2. 문제 — "자라는데 안 보인다"

### 2.1 ⚠️ EQUIPMENT 메뉴가 전투에 **영향이 없다** (결함)

전투는 장비 스탯을 **읽는다**:
```
src/core/combat/state_actions_programs.ts:75
  const equipStats = state.equipmentLoadout.totalStats();
```
그런데 `state.equipmentLoadout` 는 **항상 `EMPTY_LOADOUT`** 이다:
- `state.ts:135`·`state.ts:501` 에서 빈 것으로 생성되고 **이후 아무도 갱신하지 않는다**.
- 메뉴 장비 화면은 **별개 객체** `this.equipmentLoadout` 을 고치는데(`main.ts:902`), 런 시작 시 `main.ts:1662` 가 그걸 **빈 값으로 덮어쓴다**.
- 게다가 그 객체는 localStorage 에 **저장되지 않아** 새로고침에도 사라진다.

→ **장비를 껴도 수치가 1도 안 바뀐다.** "전투를 반복해 장비로 강해진다"는 축이 **화면만 있고 게임에 없다.**

### 2.2 크래프팅(Info Market) 고리가 끊겨 있을 가능성
- 지갑(`this.inventory`)은 런 시작 시 **미션 보상으로 덮어써진다**(`main.ts:1661`). 런에서 번 재료가 다음 런의 제작으로 이어지는지 **불명확** — 감사 필요.

### 2.3 "얼마나 강해졌는지" 읽을 곳이 없다
- 덱은 손패로만 보인다. **덱 크기·평균 tier·고유 보유·최대 HP 증가분**을 한 곳에서 보여주는 화면/HUD 가 없다.
- 성장 순간(카드 획득·고유 획득·최대 HP 상승)에 **연출이 없다** — 같은 loot 화면이 매번 같다.

### 2.4 회복이 성장과 경쟁했다 (ADR-0319 로 절반 해결)
- 수리 슬롯이 카드와 경쟁 → 모르는 플레이어는 필패(g5 4.3% vs 26.9%).
- ADR-0319 의 **전투 후 자동 floor** 로 회복이 성장 자리에서 빠졌다. 이제 전리품 정지가 **성장의 자리**다.

## 3. 계획

우선순위는 "**보이는가**"가 아니라 "**실재하는가 → 보이는가 → 선택인가**" 순으로 잡는다(안 보이는 성장을 먼저 만들면 거짓말이 된다).

### P0 — 실재하게 (결함 수정)

| # | 작업 | 근거 / 파일 |
| --- | --- | --- |
| P0-1 | **장비 배선**: 메뉴 loadout 을 (a) localStorage 에 영속, (b) 런 시작 시 `state.equipmentLoadout` 에 주입 | `main.ts:457/902/1662`, `state/state.ts:135` |
| P0-2 | **크래프팅 고리 감사**: 런에서 얻은 재료가 제작으로 이어지는지 확인·수정 | `main.ts:828/849/1661` |
| P0-3 | 장비·제작이 밸런스에 미치는 영향 **측정**(`npm run balance`/`survival`) 후 제안 | — |

> P0 는 **밸런스 수치를 바꾼다** → 수치는 측정해 **제안**하고 오너가 결정한다(기존 규약).

### P1 — 보이게 (비주얼)

| # | 작업 | 내용 |
| --- | --- | --- |
| P1-1 | **성장 HUD/패널** | 덱 크기 · 평균 tier · 보유 고유 · 최대 HP(+증가분) · prep 지갑을 한 화면에 — **부분**: ADR-0320 이 손패에 **실피해 열**을 넣어 "이 카드가 얼마나 세게 때리는가"를 보이게 했다 |
| P1-2 | **성장 순간 연출** | 카드 획득/고유 획득/최대 HP 상승에 각각 다른 VFX·문구 — **부분**: ADR-0320 이 **피해 크기에 비례하는** 연출(armor_block · 흔들림 3px)을 넣었다 |
| P1-3 | **전리품 정지 재구성** | 슬롯을 "성장 / 정보 / 정리"로 묶어 보여주기 — 지금은 8슬롯이 평면 나열 |

### P2 — 선택이 되게 (선택지)

| # | 작업 | 내용 |
| --- | --- | --- |
| P2-1 | **수리 슬롯 → 성장형 검토** | 회복이 자동이 됐으니 "수리"를 **+최대 HP**(영구 성장)로 바꾸면 몸이 자란다. 단 g5·g6 이 수리에 의존하므로 **측정 후** 결정 |
| P2-2 | **카드 업그레이드** | 같은 카드를 두 번 먹으면 tier 상승? — 성장이 "더 세진다"로 보이는 가장 직접적인 방법. 밸런스 측정 필수 |
| P2-3 | **메타 진행 트랙** | prep 지갑·Far Grid·업적을 한 "진행" 화면으로. 런 사이의 성장을 보이게 |
| P2-4 | **런 mutators 해금** | `state/run_mutators.ts` 의 5종을 진행 보상으로 개방(현재 미배선) |

## 4. 측정 계획

모든 P0/P1/P2 는 **같은 하네스**로 전후를 잰다:

```
cd web
npm run balance     # 단일 교전 승률·턴·HP
npm run survival    # 미션 단위 (등급별)
npm run campaign    # 계약 단위 (3미션)
```

- **P0-1(장비)** 은 밸런스에 직접 영향 → loadout 이 몇 pp 를 움직이는지 먼저 측정해 **제안**한다.
- **P2-1/P2-2** 도 동일. 수치 변경은 오너 결정.
- P1(비주얼)은 **ADR-0300 텍스트 잘림 가드**와 e2e 로 검증(수치 무영향).
