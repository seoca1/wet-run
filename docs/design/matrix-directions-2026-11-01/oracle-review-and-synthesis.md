# Matrix 방향 — Oracle 교차검증 + 종합 (2026-11-01)

Manus 개념 패스(`manus-concepts.md`)에 대한 **적대적 실현성·설계 정합 검증**과 종합.
이 문서는 **제안**이며 채택된 결정이 아니다. 오너 판단 대상.

## 1. 두 프레이밍 모두 부분적으로 틀렸다 (Oracle)

- **"결정 밀도가 먼저"** 진단은 **A 이전에는 맞았지만 지금은 불충분**하다 — 경로 선택(슬라이스 1)과
  PROBE/BYPASS/BREACH/JACK OUT(슬라이스 2)이 이미 출하됐다.
- 오너의 **"던전 이동 느낌이 좋았다"**는 **런 전체에 타일 이동이 필요하다는 증거가 아니다** — 오너가
  반응한 것은 **현존감(presence) · 직접 조작 · 리듬 · 눈에 보이는 이동**일 수 있다.
- **핵심 재구성**: 이제 공간화는 **이미 존재하는 결정을 구현화**하므로 **ADR-0060의 실패 모드를 피한다.**
- 단, 반복 플레이에서 **지배 경로/동사**가 드러나면 공간화가 구제하지 못한다 — 그건 여전히 결정 밀도·밸런스 문제.

## 2. 실현성 (있는 것 vs 지어야 할 것)

| 방향 | 이미 있는 것 | 실제로 지어야 할 것 | 판정 |
|---|---|---|---|
| **한 화면 기하 기반 보드** | `Room{x,y,w,h}` · 생성 공간이 **7×5 ~ 15×10** · 이동 선택/확인 상태 | 좌표를 `dungeonToMatrix`에서 **보존**, 간선·노드 렌더, 공간 타게팅, 선택 상세 패널, 짧은 이동 피드백 | **진짜 가능 · 승자** |
| 추상 레이더/토폴로지 보드 | 완전한 인접 그래프 + 노드 상태 | 결정적 레이아웃 + 보드 렌더 | 가능·더 저렴하나 **"또 다른 UI"로 각하될 가능성** |
| **타일 걷기로 런 전체** | 타일 이동·`@`·벽·FOV·엔티티·렌더러 | 런 HP/덱/보상/세이브 통합, 충돌 자동처리 교체, A 동사 보존, 복도 수정 | ⚠️ **"B의 변장"** — 렌더러 교체가 아님 |
| LOS 스텔스 / **FOV 자원화** | 시야 반경·탐험 맵 | 감지 상태, LOS 인지 AI, 패스파인딩, 경계 기억, 밸런스, 세이브 | **새 게임** |
| 카메라 추적 / 심우주 스트리밍 | 없음 | 카메라, 청크 수명, 영속성, 스폰, 목표 추적, 길찾기 복구 | **새 게임** (Pillar 1 위험) |

**크롤러는 보기보다 재사용 불가**: 이동이 자동으로 공격·문·아이템·함정·계단을 처리(`dungeon_crawler_actions.ts:293`) → **명시적 동사와 정면 충돌**. 복도가 **그래프 간선을 무시**(`dungeon_crawler_generation.ts:192`). AI가 좌표로만 추격(LOS 미검사). 카메라 없음(큰 맵은 좌상단 기준 잘림).

## 3. 반드시 지켜야 할 결정층 규칙 (ADR-0060 재발 방지) — **협상 불가**

| 공간화의 실패 | 규칙 |
|---|---|
| 안개가 합법 경로를 숨김 | **현재 인접·간선은 항상 표시.** Probe/SCAN은 위협 *상세*만 숨긴다, 위상은 절대 아님 |
| 스크롤이 보스·대안을 숨김 | **전체 위상이 한 화면.** 보스는 **상시 `◆`** (나침반 힌트 아님) |
| 이동이 선택을 대체 | **화살표 = 선택, Enter = 확정.** 최근접/보스방향 자동 선택 금지 |
| 도착이 내용을 자동 처리 | 도착이 **동사 오버레이를 열 수는 있으나 기본 선택·자동 실행 없음** |
| 미니맵이 진짜 결정면이 됨 | **별도 미니맵 금지** — 보드가 세계이자 조작면 |
| 그림이 연결을 발명 | **`MatrixNode.adjacent`가 권위.** 간선 없는 복도 금지, 간선 누락 금지 |
| 색이 의미를 지움 | `@` · `◆` · 간선 스타일 · `NEW/SEEN/CLEAR` · 선택 글리프 **병기** |
| 걷기가 복도세를 만듦 | **한 번의 확정된 간선 이동 = 한 번의 경로 행동.** 결정 사이에 빈 타일 걸음 금지 |

## 4. "한 화면 · 스크롤 없음" 은 자기기만인가? — **아니다**

생성 기하가 **15×10**을 넘지 않아 모든 지원 캔버스 형태에 들어간다. 라벨은 방마다 붙이지 않고
**선택 노드 상세 패널**로 보낸다. 자기기만이 아니게 되는 조건: ① `@`가 **지속적 위치**를 가짐
② 입력이 **공간적으로 안정된 이웃**을 타게팅 ③ 선택한 간선이 **눈에 보이게 확정·이동**됨
④ **도착이 가능한 행동과 결과를 바꿈**. (정적 네트워크 그림 + 행 커서는 여전히 선택 화면일 뿐이다.)

## 5. 순위 (오너 만족 × 기둥 정합 ÷ 비용 × 위험)

| 순위 | 방향 | 만족 | 기둥 | 비용 | 위험 |
|---|---|---|---|---|---|
| **1** | **기하 기반 오퍼레이션 보드 (노드 스케일 이동)** | 높음 | 높음 | 낮음~중간 | 낮음~중간 |
| 2 | 추상 레이더/토폴로지 보드 | 중~높음 | 높음 | 낮음 | 낮음 |
| 3 | 전술 AI 없는 압축 타일 걷기 | 초기 높음 | 중간 | 중~높음 | 높음 |
| 4 | 로밍 ICE 포함 완전 크롤러 런 | 잠재 높음 | 중간 | 높음 | 매우 높음 |
| 5 | 기존 목록 + 이동 애니메이션 | **명시적 낮음** | 높음 | 낮음 | **제품 각하** |
| 6 | 심우주 스트리밍/자유 비행 | 미지 | 낮음~중간 | 매우 높음 | 매우 높음 |

## 6. 종합 권고 (Manus × Oracle 수렴)

**두 출처가 같은 승자를 지목했고, 같은 위험을 지목했다.**

> **한 화면 · 기하 기반 오퍼레이션 보드**: `@`를 **지속 토큰**으로 두고, 노드를 생성 좌표의 **방**으로,
> 간선을 **권위 있는 경로선**으로 그린다. 화살표로 **눈에 보이게 연결된 이웃**을 타게팅 → Enter로 **이동 확정**
> → 도착 노드에서 **기존 PROBE/BYPASS/BREACH/JACK OUT** 동사. 목록 작업은 **선택 노드 상세 카드**로 흡수.

**수렴한 공통 위험**: Manus는 자기 권장안의 최대 위험을 *"던전 모양으로 꾸민 노드 목록"* 이라 했고,
Oracle은 *"동사를 싣지 않은 표현은 ADR-0060의 실수를 반복"* 이라 했다 → **§3의 규칙 8개가 그 답**이다.

**삭제할 것 (짓지 말 것)**:
- **목록을 주 상호작용에서 삭제** — 특히 `DEPTH / ZONES (not routes)` 스택과 그 범례(`matrix_nodes.ts:111`).
  단 **안정 ID·노드 상세는 보드 옆 정보로 유지**.
- 미니맵 · 카메라 · FOV 자원화 · LOS AI · 스트리밍 **짓지 않는다**.
- 독립 크롤러는 **ADR-0246 C를 위해 남기되, 그 규칙을 런에 들여오지 않는다**.

**가장 레버리지 큰 한 가지 변경**:
> **경로 선택이 행 커서가 아니라 아바타를 조작하게 한다** — 화살표는 연결된 방을 타게팅, Enter는 `@`를
> 그 간선 너머로 이동, 동사는 그 방에서 작동. 현재 리듀서·그래프·ID·상태·조우 메뉴와 **호환**된다.

**비용 중간 · 확신 중간** (구조 적합성은 강하지만, 오너 만족은 스크린샷이 아니라 **상호작용으로만 확인**된다.)
