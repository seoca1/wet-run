# ADR-0310: 각 셀은 자기 주사위를 가진다 — 계측기의 기본값

**상태**: Accepted
**날짜**: 2026-11-12
**결정자**: 사용자 ("응.")
**우선순위**: P1 (검증 · 기준선)

## 컨텍스트 (Context)

`mission_survival` 은 스윕 시드마다 `Math.random` 을 **한 번만** 시드하고 미션을
카탈로그 순서로 걸었다. 그래서 한 셀(미션 × 시드)의 결과가 **먼저 돈 미션들에 의존**했다.

증상은 두 가지였고, 둘 다 g6 작업 중에 드러났다.

1. `--grade` 필터 유무로 **같은 셀**이 다른 값을 냈다.
2. 한 등급의 정책 변경이 **다른 등급**을 최대 1.7pp 움직였다.

측정(g6 = 96/192 셀, 최적 정책):

| 스트림 | 전수 스윕 | `--grade 6` | 차이 |
|---|---:|---:|---:|
| 공유 · 32시드 | 33.3% | 35.4% | +2.1pp |
| 공유 · 64시드 | 35.4% | **39.6%** | **+4.2pp** |
| per-cell · 32시드 | 31.3% | 31.3% | 0.0pp |
| per-cell · 64시드 | 32.3% | 32.3% | 0.0pp |

64시드 공유 필터 실행 39.6% 는 목표 30 대비 **+9.6pp** — 허용 8pp 를 넘는 **MISS** 다.
같은 셀을 per-cell 로 재면 32.3%, **+2.3pp 로 통과**한다. **계측기가 결정의 통과 여부를
바꿨다.** ADR-0309 의 g6 여유도 +5.4pp 가 아니라 +2.3pp 였다.

이 프로젝트는 이미 같은 교훈을 두 번 기록했다: ADR-0303/0304(계기가 틀렸다)와
ADR-0265(소크 census 를 per-cell 로 고침).

## 고려한 옵션

### Option 1: 공유 스트림 유지
- **장점**: 기록된 모든 표가 그대로 재현된다. 코드 무변경.
- **단점**: 필터가 답을 바꾸고, 등급 간 이동이 실제 규칙 효과와 섞인다. 새 결정마다
  "이 1.7pp 는 규칙인가 순서인가"를 다시 물어야 한다.

### Option 2: per-cell 플래그 유지(기본 off)
- **장점**: 과거 수치 재현과 새 측정을 모두 할 수 있다.
- **단점**: 아무 표시 없이 기본 명령을 돌리면 **편향된 수치**가 나온다. 실제로 이 세션에서
  `--per-cell` 을 붙이지 않은 35.4% 를 결정에 인용했다.

### Option 3: per-cell 을 기본값, `--shared-stream` 으로 과거 재현 (채택)
- **장점**: 기본 명령이 **정직한** 수치를 낸다. 과거 표는 플래그 하나로 재현된다.
  필터와 전수 스윕이 일치하므로 "필터로 빠르게 확인"이 신뢰할 수 있는 절차가 된다.
- **단점**: 기본 출력이 바뀐다 — 현재 기준선을 인용하는 문서를 갱신해야 한다.
  Accepted ADR 의 표는 역사적 기록이라 **고치지 않는다**(결정 내용 불변).

### Option 4: per-cell 만 남긴다
- **장점**: 계측기가 하나뿐이라 혼동이 없다.
- **단점**: ADR-0280/0306/0309 의 표를 **재현할 수 없다**. 역사적 수치의 재현 경로는
  남겨야 한다.

## 사용자 결정 (Decision)

- [x] **Option 3** — per-cell 기본값 + `--shared-stream` 재현 경로

## 결과 (Consequences)

- `PER_CELL = !argv.has("--shared-stream")`. `--per-cell` 은 받아도 무해(이미 기본).
- 헤더가 모드를 말한다: `· per-cell seed` 또는 `· shared stream (historic)`.
- **새 기준선(per-cell, 32시드, `--policies`)**:

  | grade | default | optimal | gap |
  |---|---:|---:|---:|
  | 1 | 100.0 | 100.0 | +0.0 |
  | 2 | 77.0 | 96.5 | +19.5 |
  | 3 | 47.2 | 74.4 | +27.3 |
  | 4 | 36.6 | 50.6 | +14.1 |
  | 5 | 5.2 | 29.9 | +24.7 |
  | 6 | 2.1 | 31.3 | +29.2 |

- **미션 완주율 기준선(per-cell, 64시드)**: `100 / 97.1 / 75.9 / 51.4 / 26.9 / 32.3`
  vs 목표 `100/95/80/50/25/30` → 최대 이탈 **4.1pp**.
- **결정성**: 같은 실행을 반복하면 같은 카운트. 필터 실행도 전수 스윕과 동일.
- **재기준화 정책**: Accepted ADR(0280/0306/0309)의 표는 **역사적 측정**으로 보존하고,
  현재 기준선을 인용하는 곳은 per-cell 값으로 갱신한다. ADR-0309 의 여유는
  `## Implementation Status` 주석으로 정정한다(결정 내용 불변, ADR-0195).

## 열린 질문

- **(a) 나머지 계측기.** `curve_probe.ts` · `search_curve_constrained.py` · `tune_curve.py` 가
  각자 시드 규약을 갖는다. 같은 "셀 독립" 감사를 적용할지 별도로 봐야 한다.
- **(b) 과거 표의 재측정.** ADR-0280/0306 의 표를 per-cell 로 다시 재면 목표 곡선의
  해석이 달라질 수 있다(현재 g6 32.3 vs 기록 35.4). 결정은 유지되지만, "얼마나 여유가
  있는가"는 재측정 가치가 있다.
- **(c) 고정 기준선 파일.** 지금은 기준선이 로그와 ADR 표에 흩어져 있다. per-cell 기준선을
  한 파일(예: `docs/design/baseline.json`)로 두고 테스트가 대조하면 드리프트가 줄어든다.
